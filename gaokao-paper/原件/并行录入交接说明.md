# 多窗口并行录入 · 交接说明

**给新开的录题窗口看这份就够了。**

---

## 一、三句话结论

1. **可以并行**，但**入库必须串行**——录题窗口只写 `input_batchXX.py`，不碰 `bank.json`
2. **先认领再开工**，用 `claim.py` 占住题型段，避免两个窗口录同一批
3. **只读你那几页原文**（2.2 MB），别下载 21 MB 的完整 PDF

---

## 二、为什么不能各自入库

`hand_input.add()` 是**读-改-写**：

```python
bank = load()      # 读整个 bank.json
bank.append(q)
save(bank)         # 整份写回
```

两个窗口同时跑，后写的**整份覆盖**先写的——先录的题直接消失。

而且 `next_id()` 靠遍历 bank 取最大序号，
两个窗口会拿到**同一个 ID**（都算出 M-H0262）。

所以：**录入并行，入库唯一。** 这是整个方案的基石。

## 三、完整流程

### 第 0 步：领任务

```bash
python3 tools/claim.py                 # 看谁占了哪段
python3 tools/claim.py 窗口A 4         # 认领 4 个题型（约 16 题）
```

输出会告诉你领到了哪几个题型、各多少题。
**认领记录在 `tools/_claims.json`**，别的窗口看得到，不会撞车。

### 第 1 步：看页码

打开 `原件/题型页码索引.md`，找你认领的题型，看对应的 PDF 页码和原文文件。

> **页码基准**：索引和 `pXXX.txt` 是 **1-based**；
> `dump_pdf.py --pages` / `pdf2latex.py --page` 是 **0-based**。
> 索引写第 33 页 → 用 `--pages 32`。

页码标 `?` 的（结束页无法确定）用特征词搜：

```bash
python3 tools/dump_pdf.py <pdf> --find '题干里的特征短句' --context 1200
```

### 第 2 步：读原文（不下载 PDF）

```bash
cat 原件/按页原文/p033.txt
```

456 个 txt 共 2.2 MB，比 21 MB 的 PDF 快一个数量级。

**只有这几种情况才需要原件**：

| 场景 | 命令 |
|---|---|
| 符号存疑，看字符码位 | `dump_pdf.py <pdf> --pages 32 --chars` |
| 切图题 | `cut_figs.py <pdf> --list 45` |
| 分数、根号（矢量绘制，文本层没有） | 只能看 PDF 图象 |

### 第 3 步：写 input 文件

```bash
python3 tools/new_batch.py 18 -t M-T-027:E1,V1,V2,V3    # 生成骨架
# 然后填 stem_text / opts / answer / solution / review
```

**纪律：只写 `tools/input_batchXX.py`，绝不执行入库命令。**

（`new_batch.py` 本身不写 bank，安全。`commit_batch*.py` **会写 bank，别跑**。）

### 第 4 步：完工释放

```bash
python3 tools/claim.py 窗口A --release
```

### 第 5 步（合并窗口）：统一入库

```bash
python3 tools/merge_batches.py --all --dry-run    # 先看会入什么
python3 tools/merge_batches.py --all              # 实际入库
```

一次 `load` → 全部追加 → 一次 `save`，**ID 由同一次分配，必然不冲突**。

已入库的题会被自动跳过，不会重复录。

---

## 四、防重复的三道闸

| 闸 | 位置 | 作用 |
|---|---|---|
| 1 | `claim.py` | 开工前占坑，人不撞人 |
| 2 | `merge_batches.py` 按**题号** | `src` 里的 `M-T-060-E1` 已在 bank → 跳过 |
| 3 | `merge_batches.py` 按**题干签名** | 老格式没题号，归一化后比对题干 |

第 3 道闸是必需的：第 2~7 批的骨架用老格式（`topic`/`kind`，没有唯一题号），
只靠题号判重会**漏判 132 题**，一次 `--all` 就全重复录进去。

---

## 五、各窗口能碰什么

| 文件 | 录题窗口 | 合并窗口 |
|---|:---:|:---:|
| `原件/按页原文/*.txt` | 读 | 读 |
| `tools/input_batchXX.py` | **写** | 读 |
| `tools/_claims.json` | 写（认领） | — |
| `data/bank.json` | **绝不碰** | 唯一写者 |
| `data/ref_bank.json` | 读 | 读 |
| `tools/_merged.json` | — | 写 |

## 六、合并后的收尾

```bash
python3 tools/run_batch.py <批次号> --no-commit
```

跑：导出 HTML/Word/答案卷 → 两端核对 → 三项回归 → 刷新清单/勘误表/页码索引。
