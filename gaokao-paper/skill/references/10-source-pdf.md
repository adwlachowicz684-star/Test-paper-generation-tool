# 来源：PDF

## 先判断：文字版还是扫描件

```python
import pymupdf
d = pymupdf.open(path)
n = sum(len(d[i].get_text().strip()) for i in range(min(5, d.page_count)))
print('前5页字符数', n, '页数', d.page_count)
# n < 200  → 扫描件，转 12-source-image.md
# n > 500  → 文字版，可继续
```

**只收文字版。** 扫描件经 OCR 后公式必错，修正成本高于重新找文件。

## 模式 A（人工审核）—— 主要用法

PDF 只是**阅读对象**，不跑提取脚本。流程：

1. 把全文 dump 出来定位题目原文

```python
import pymupdf
d = pymupdf.open(path)
FULL = '\n'.join(d[i].get_text() for i in range(d.page_count))
i = FULL.find('题干里的特征词')
print(FULL[i-500:i+2500])     # 连上下文一起看，含【答案】【详解】
```

2. 读原文，**理解语义**后按 `20-latex.md` 重建题干
3. 用【详解】反推题干自洽性（见 `21-review-rules.md`）
4. `hand_input.add_many(...)` 入库

**关键：一定要同时读【答案】和【详解】**，不只是题干。
详解是校验题干正确性的唯一依据——已经靠它抓到过原卷笔误。

### dump 全文的注意事项

PDF 文本提取结果是**按视觉行**排列的，公式会被拆成多行：

```
f 1
2 + x              ← 这是 f(1/2 + x)
    
    
```

`` 是花括号的矢量绘制（提取成乱码）。看到这种结构就说明那里原本是分数或函数括号。

连续多行短文本 + 孤立数字 = 大概率是分数，要还原成 `\frac{}{}`。

## 模式 B（脚本提取 + 核对）

适用于语文、英语等公式少的科目：

```bash
python3 py/main.py extract --pdf <路径> --subject 语文
# 不加 --no-commit 才写库；想先核对就加
```

提取后**必须逐题核对**，重点看：

- 题干尾部是否有多余的 `（ ）`（原卷作答位，见 `21-review-rules.md`）
- 选项是否齐全（4 个）
- 题号是否连续无重复

## 已知的提取器行为（模式 B/C 用得上）

如果需要排查脚本提取的结果，这些是已实现并验证过的规则：

| 规则 | 说明 |
|---|---|
| 多栏切分 | 数学 2021–2025 是三栏拼版，先按栏切再栏内聚行 |
| 栏位聚类 | 用全卷累积的题号 x 坐标聚类，容差 12 |
| 题号识别 | `0.` 无效；`11.8` 这类小数不算题号 |
| 卷头跳过 | 第一个分节标题之前一律视为卷头 |
| 选项跨行累积 | 带分数的选项会被拆行，必须累积到下一个字母标记 |
| 选项标记格式 | 兼容 `A．` / `A.` / `(A)` / `（A）` |
| 图片选项行 | 整行只剩孤立大写字母时视为图片选项 |
| 上下标源信息 | 用字体名设计尺寸 + 基线偏移判定，非绝对阈值 |
| 作答位清洗 | 题干尾部空括号去重保留一个 |
| 泄漏选项切回 | 作答位之后的选项切回 `opts` |

**完整清单与踩坑记录见项目 `README.md`**，本 skill 不重复。

## 常见失败与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 提取出 0 题 | 扫描件 | 转图片流程 |
| 题干里混有「第 3 页 共 8 页」 | 页脚未清 | 已实现正则清除，若仍出现报 bug |
| 三栏卷题号错乱 | 栏位聚类失败 | 检查是否末页题目少导致样本不足 |
| 图片归属串行 | y 区间匹配 | 已改为归属上方最近的题号 |
| 末页空白 | 解答题留白溢出 | 已实现自动缩减重排 |
