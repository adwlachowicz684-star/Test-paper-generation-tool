# 全局重复题检测：`tools/dupcheck.py`

```bash
python3 tools/dupcheck.py                  # 扫全库，生成候选清单
python3 tools/dupcheck.py --threshold 0.80 # 调阈值（默认 0.60 起报）
python3 tools/dupcheck.py --only bank      # 只扫已录题库内部
python3 tools/dupcheck.py --apply          # 按人工审核结果写回
```

## 为什么是全局，不是每题跑一遍

每录一题跑一次全库 = O(n²) 次解析，而且**新题与旧题重复时旧题已录进去了**，
事后发现就得返工。全局一次扫完，重复关系一次看清，
还能发现「两道都已录入的题其实同题」。

## 算法：级联，从便宜到贵

去重领域的标准分层，按代价递增：

    C(精确哈希) << C(分块) << C(n-gram 相似度) << C(语义向量)

| 层 | 方法 | 作用 |
|---|---|---|
| 1 | 精确签名（make_plan 已在做） | 抓完全一样的，零成本 |
| 2a | **Blocking**：按 (统一题型, 答案) 分桶 | 只比桶内，1631 题 → 约 6 万对 |
| 2b | **数字倒排兜底** | 抓选项重排导致答案字母不同的 |
| 3 | **长度过滤** | 长度比 <0.6 直接跳过 |
| 4 | **字符 3-gram + Jaccard** | 真正算相似度 |

### 为什么没用 MinHash / LSH

那是**万亿级语料**才必需的。本库 1631 题，分块后候选约 6 万对，
暴力 Jaccard 几秒跑完。上 MinHash 会引入**近似误差**和调参负担
（band 数、行数、哈希函数个数），
对这个规模是杀鸡用牛刀，反而可能**漏判**。

判据很简单：先量一下分块后的候选对数，百万以内直接暴力。

## 四个通道（对应「类型、答案、关键词、公式主要文本」）

| 通道 | 内容 | 权重 |
|---|---|---|
| `txt` | 公式拍平后的字符 3-gram | 0.40 |
| `num` | 数字集合 —— 数学题最强的判重特征 | 0.30 |
| `key` | 关键词：变量名 + 函数名 | 0.15 |
| `opt` | 选项集合（仅选择题） | 0.15 |

**缺失的通道不参与加权，权重重新归一化。**
已录题有 LaTeX、素材题只有破碎文本，若某通道为空按 0 分算，
会把真同题误判为不重复。这是必须剔除的原因。

### 数字为什么权重这么高

数学题换数字就是换题，同题数字必然一致。实测同题对的
数字集合 Jaccard 通常 = 1.0，不同题很难撞全。
它也是最便宜的粗筛——先比数字能砍掉绝大部分候选。

## 关键：公式「拍平」

两侧形态不同，必须对齐才能比：

```
bank   $a=6\ln\pi,\ b=3\pi\ln2$   →  拍平 →  a=6lnπ,b=3πln2
ref    a = 6lnπ，b = 3πln2         →  拍平 →  a=6lnπ,b=3πln2
```

规则：去 `$`、`\left`、`\right`、花括号、空白；
**有语义的命令还原为字符**（`\pi`→π、`\ln`→ln），其余命令删除但保留参数。

映射表在脚本顶部的 `CMD`。**换教辅时若出现新符号，往这里加。**

## 两个必须注意的坑

### 1. 分块键不能用 `type` 字段

bank 的 type 是 `选择/填空/解答`，ref_bank 的 type 全是 `例题`
（真正的题型在 `kind`：典例/变式）。直接按 type 分块，
**跨库对永远不会进同一个桶**，等于只扫了库内。

统一办法：用 `len(opts) >= 2` 判断是否为选择题。
ref_bank 的 opts 数量只有 4 或 0，恰好对应选择 / 非选择，判据可靠。

### 2. src 题号必须用正则提取

老题 src 写作 `2024热点题型归纳 M-T-009-V4`，**没有 `·` 分隔符**，
用 `split('·')[-1]` 会返回整串，导致「已录题 ⟷ 它的素材源」
这对正常对应关系排除不掉，几百对全是噪音。

正确做法：`re.search(r'(M-T-\d+-(?:E\d+|V\d+))', src)`。

## 人工审核（不可省）

脚本只给候选，**不自动判定**。三档：

| 档 | 分数 | 说明 |
|---|---|---|
| 高 | ≥0.90 | 几乎必是同题，但仍可能只是「换了数字」的变式 |
| 中 | 0.75~0.90 | 需人工判断 |
| 低 | 0.60~0.75 | 仅备查 |

**为什么高分也不能自动判**：实测抓到过
`f(x)和g(x)…g[f(x)]不可能是` 与 `…g[f(x)]有可能是` 这一对，
文本相似度高达 0.693，但一个问「不可能」一个问「可能」，
是**变式题不是重复题**。这种语义反转只有人能看出来。

### 审核流程

1. 跑扫描，得到 `重复题候选清单.md` + `tools/_dup_candidates.json`
2. 人工看清单，在 json 里给每对填 `"verdict"`：
   - `"dup"`　确认同题
   - `"not"`　不是同题
   - 留空　　还没看
3. `python3 tools/dupcheck.py --apply` 写回 `data/skipped.json`
4. 重跑 `make_plan.py` 刷新清单

### 保留谁、标记谁

不能按 a/b 顺序（顺序由分数排序决定），要看库别：

- 一边已录(bank)、一边素材(ref) → **保留已录的**，标记素材为重复
- 两边都是素材 → 保留 a，标记 b
- 两边都已录 → **不自动处理，只告警**（要从 bank.json 删题，影响面大）

另外，**精确判重已覆盖的项不会重复写入** skipped.json，
避免干扰 make_plan 的状态统计。

## 阈值校准

0.60 是保守起报值（宁可多报不漏）。跑完看高档的准确率再调：
若高档误报多 → 调高到 0.70；若明显漏了已知重复 → 调低到 0.55。

经验参考（大语料场景）：字符 5-gram + Jaccard ≥0.85 偏严格、0.7 偏宽松。
本题库题干较短，用 3-gram 更合适。
