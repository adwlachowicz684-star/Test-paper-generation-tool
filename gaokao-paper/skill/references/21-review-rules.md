# 人工审核规则

模式 A 的核心。**跑完这些检查才算审完一道题。**

## 检查清单

- [ ] 题干里每个函数都带括号（`f(x)` 不是 `f x`）
- [ ] 每个区间都带括号（`[0,1]` 不是 `0,1`）
- [ ] 分数写成 `\frac{}{}` 而非上下两行残留
- [ ] 上下标正确（`x₁` 下标 vs `x²` 上标）
- [ ] 数集写作 `\mathbb{R}`（渲染为 R，不是 ℝ）
- [ ] 选择题题干末尾有且仅有一个 `（　　）`
- [ ] 选项齐全且字母不重复
- [ ] 答案在选项范围内
- [ ] **用【详解】反推过题干，确认自洽**
- [ ] `review` 字段写清改了什么、为什么改

前五项针对 PDF 提取的固有缺陷（矢量括号、分行分数、上下标压平），
每次都要查。

## 上下标歧义：靠上下文判定

**「字母+数字」天然有歧义**：`x3` 可能是 `x³`（立方）也可能是 `x₃`（下标）。

三条规则，置信度递减：

| 规则 | 模式 | 例 | 依据 |
|---|---|---|---|
| 1 | 大写+数字 | `F1` `P2` `A1B1C1` | 几乎必是下标 |
| 2 | 字母+n | `an` `an+1` `a2n` `Sn` | 数列项 |
| 3 | 小写+数字 | `x1` `x2` | **仅当同题干有「该字母+n」** |

规则 3 是关键：`x1, x2, …, xn` 里同时存在 `xn`，说明是下标序列；
没有这个证据的一律不动——`x3 = x³`、`y2 = y²`、`b2 = b²` 都是上标，改了就错。

**拿不准时保持平文本。**

这不是保守——判错的代价不对称：
- 判成平文本 → 卷面少一个上下标，不影响做题
- **上标判成下标** → 语义完全变了，孩子会算错

平文本是可逆的（后面还能改），判错则可能一直错下去。

## 改了答案要留痕，并进勘误表

判定原书有误、按正确答案录入后，两件事都要做：

**1. 写进 review**（必做）。写清「原书是什么 → 改成了什么 → 凭什么改」，
后来复核的人不看这条就无法判断改动是否成立。

```python
'review': (
    r"**原书答案 C（2 个）有误**：详解只列了 {1,2,3}、{1,2,4}，"
    r"遗漏了 {1,2,3,4}。真包含要求 A\neq\{1,2\}，而 {1,2,3,4} 满足，"
    r"故实为 3 个，答案应为 B。已按正确答案录入。"
),
```

**2. 进勘误表**（A 类时必做）。原书答案真被改动的，把结论补进
`tools/gen_errata.py` 的 `A_MANUAL` 列表（含原书答案、现录入、依据），
然后重跑：

```bash
python3 tools/gen_errata.py     # 生成《原书勘误表.md》
```

分四类，别混：

| 类 | 含义 | 是否要手工补 A_MANUAL |
|---|---|---|
| **A** | 原书【答案】本身判错并改动 | 要 |
| **B** | PDF 提取丢符号 → 还原（原书无误） | 否，只加题号到 B_KEYS |
| **C** | 答案未改，仅详解/选项笔误 | 否，只加题号到 C_KEYS |
| **D** | 存疑，按原书保留 | 否，只加题号到 D_KEYS |

**B 类和 A 类最容易混。** 判断标准：证据链指向"原书就印错了"才是 A；
只是提取环节丢了根号/上标/括号，原书本身没错的，是 B。
把 B 误记成 A，等于给原书泼脏水；把 A 漏成 B，孩子会按错答案练。

## 原卷笔误：以【详解】为准

**这是人工审核最有价值的部分，也是唯一无法自动化的环节。**

判断方法：读【分析】和【详解】，看它实际在计算什么，
反推题干应该是什么。

### 实例 1：负号丢失

```
题干：  则方程 f(x)=1 在区间 (-1,11) 上所有实根之和是
详解：  全程计算 f(x)=-1，得出 30
答案：  A（30）

判定：题干的 =1 是笔误，应为 =-1
```

**依据链**：详解全程算 `f(x)=-1` + 答案 30 与 `-1` 的计算结果吻合
→ 题干的 `1` 丢了负号。

### 实例 2：数字不自洽（按详解录入 + 标注存疑）

```
题干：  若 f(2021) - 1/2 = f(-1)
详解：  f(1) = 1/3
```

按题干字面推：`f(1) - 1/2 = -f(1)` → `f(1) = 1/4`，与详解的 `1/3` 矛盾。

**处理方式**：按详解口径录入（答案 C 是按 `1/3` 算出来的），
然后在 `review` 里写明冲突点。

这样后面复核的人能看到完整推理链：知道这里存在两种可能、
为什么选了详解口径。

```
'review': '原卷「f(2021)-1/2 = f(-1)」与详解「f(1)=1/3」不自洽，'
          '按详解口径录入，供复核时重点关注。'
```

### 判断优先级

```
答案 + 详解  →  最强证据（答案决定最终结果）
详解推导过程 →  次强
题干字面     →  最弱（PDF 提取还可能再丢字符）
```

三者冲突时，按上面的顺序取信。

## 作答位：去重而非删除

原卷选择题题干末尾有「（　　）」给考生填答案。

**要保留一个。** 早期版本全删了，结果卷面变成
「…单调递增的区间是 A．… B．…」，反而不像试卷。

但 PDF 提取时因为分栏/换行，**同一个括号常被重复抓取成 5 个**：

```
…的区间是（　　）（　　）（　　）（　　）（　　）
```

**规则**：先清掉尾部全部空括号，再拼上一个标准的 `（　　）`。

```
处理顺序：先剥掉句末句号，再清括号、补一个 —— 得到「…则（　　）」
幂等：重复调用不会累加
```

按题型开关：

| 题型 | 作答位 |
|---|---|
| 单选 / 多选 | ✅ 保留 |
| 填空 | ❌（用下划线 `＿＿＿＿＿`） |
| 解答 | ❌ |

## 选项

### 完整形态必须是 `(字母, 文本)` 二元组

```python
'opts': [['A', '$y=-4x-8088$'], ['B', '$y=4x+8088$'], ...]
```

字母取 `A-H`，内容非空，字母不重复——`hand_input.add()` 会校验这三项。

### 长公式选项会触发单列

含 `$...$` 的选项会被标记 `.opts-noclip`（不裁切），
且按公式真实长度分列：短选项 4 列、中等 2 列、长公式 1 列。

这是自动的，不需要人工干预。但如果发现选项在 HTML 里"只剩 ABCD 没有内容"，
见 `30-pitfalls.md`。

### 选项里漏进题干

有时选项被拼进题干，形如：

```
…二面角 C-AB-D 为 60°，则（　　） C. 当 AB⊥CD 时… D. 当 AB…
```

**处理**：把作答位之后的选项切回 `opts`，**只补缺失的字母**。

已有选项保持不动——少数题的选项被提取成了碎片（如 `A="和钉子"`），
这种必须重新拆卷。猜着覆盖会把好数据改坏，不如留原样并在 `review` 里标注。

## 教辅里的重复题

**机械提取会把完全重复的题当两道收进来。**

实例：教辅变式 17 与变式 16 题干、选项、答案全部相同。
录入时发现后跳过 17。

**检查方法**：录入前扫一眼同批次的题干首行，看有没有明显雷同。
尤其是教辅——它的变式题经常从别处抄来重复。

## 图题

带图的题：

1. 图切到 `src/slices/<科目>/`
2. 命名 `<题目ID>_<序号>.png`
3. `figs` 字段存文件名列表
4. **人工确认图里没混入相邻题目的内容**

自动切图按 y 区间，两题挨得近会切错。

## `review` 字段怎么写

**必须写。** 写清：改了什么、为什么改、有什么存疑。

好的例子：

```
'修复函数括号（f(3-x)、f(-2022)）、点坐标括号（(6,f(6))）；
 选项 C/D 的分数由上下两行还原为 \frac{1}{4}、\frac{1011}{2}。'
```

```
'原卷作 f(x)=1，据详解判定应为 f(x)=-1，已修正。'
```

```
'注意：教辅变式 17 与本题完全重复（题干、选项、答案均相同），已跳过。'
```

差的写法：

```
'已修正'          ← 改了什么？
'ok'              ← 等于没写
''                ← 空白
```

**`review` 是人工录入的唯一痕迹。** 不写的话，
三个月后没人知道这道题被改过、为什么改。


## 审核不只看答案，必须验证渲染结果

**教训**：曾录入 7 道 2022 真题，逐题验算了答案（全部正确），
但**没有检查页面渲染**。结果第 3 题显示：

```
记 overrightarrow{CA}=boldsymbol{m}
```

原因是 `\overrightarrow` 等命令未被支持，走了未知宏分支输出命令名。
**答案对了，页面却是错的** —— 用户一眼就看到了，我却没有。

**审核清单（每题必做）**：

1. 核对答案（验算）
2. **打开生成的 HTML/Word，确认公式渲染正常**
3. 检查有无 LaTeX 源码泄漏（命令名以文本形式出现）
4. 两端对照：HTML 与 Word 的结构数应一致

**自动化辅助**：生成后跑脚本，而不是肉眼看

```bash
# 1. 源码泄漏扫描（命令名出现在输出里 = 未支持）
#    见 30-pitfalls.md C3
# 2. 逐题核对：证明第 N 题在两端**都存在**
python3 tools/check_render.py \
    html/试卷_XXX.html out/试卷_XXX.docx
```

`check_render.py` 比「统计结构数」更进一步：后者只能证明数量相等，
**证明不了第 N 题在两端都在**。数量对但内容错位的情况查不出来
（答案卷题号坑就是这么来的，见 `30-pitfalls.md` B4）。

它的做法是用题干去公式后的纯中文片段做锚点，两端各查一次。
三个注意点都写在脚本 docstring 里（两端公式都要置空、
全角句号 ≠ 中文句号、填空下划线要去掉）。

## 同类命令只改一处会漏端

三端各自独立实现公式渲染：

| 端 | 文件 | 函数 |
|---|---|---|
| HTML | `py/mathml.py` | `_parse_expr` |
| Word | `py/mathml.py` + `py/extract3.py` + `py/make_paper.py` | `latex_expand` → `split_rich` → `omml_segs` |
| 前端 | `src/app/render.js` | `parseLatex` |

新增命令必须**四处同步**（Word 端是三步）。只改一处会导致
同一道题在不同端显示不一致，且不易察觉。

## 插代码前先确认函数

`split_frac` 与 `split_rich` 都有 `\frac` 分支，
`_minner` 与 `omml_segs` 都有 `\sqrt` 分支。

加分支时**两个函数都要加**，并用足够长的 anchor 唯一定位：

```python
# 用带上下文的多行 anchor，而不是单行关键字
anchor = """    if g[0] == 'f':
        out.append('<m:f>...')"""
```

定位后确认它落在预期的函数体内：`grep -n '分支关键字' 文件`。
插错函数的表现是**测试全绿但功能不生效**（新代码在不执行的分支里），
这个坑踩过三次。


### 验算：先解析降维，别用暴力双重循环

对约束优化题做数值验证时，**不要直接写二维/三重网格扫描** ——
20000×20000 的循环会直接把命令跑超时（实测两次 TimeoutError）。

先用解析法把维数降下来：

| 手段 | 例 |
|---|---|
| 固定一变量，解关于另一变量的方程 | $x+y+\frac1x+\frac9y=10$ → 对固定 $x$ 解 $y$ 的二次方程 |
| 用求根公式代替扫描 | $y^2+y(\frac1x-10+x)+9=0$ → 直接套公式 |
| 内层用极值条件闭式解 | $c\cdot g(a)+\frac5{c-2}$ → 内层对 $c$ 求导得 $c=2+\sqrt{5/g}$ |
| 三次方程用 numpy.roots | $y^3-Cy+1=0$ 的实根 |

降成单变量后 20000 点的扫描毫秒级完成，精度还更高。

### 确认教辅答案有误时，按正确值录入并写清原因

T019-V3 原书答案 $\frac{5\sqrt5}{2}\approx5.590$，
数值扫描得 $6.964776$，解析推导 $\sqrt5+\sqrt{10\sqrt5}=6.964776$，两者一致。

错误定位在：把 $\frac{5}{c-2}$ 提出 $\sqrt5$ 时写成 $\frac1t$，
实际应为 $\frac{\sqrt5}{t}$（因 $\frac5{\sqrt5}=\sqrt5$）。

录入方式：**answer 写正确值**，review 里写三件事 ——
原书给的值、错在哪一步、正确值与取等条件。
这样孩子对答案时能看到完整因果，而不是一个孤立的数字。

### 嵌套根式能正常渲染

$\sqrt{5}+\sqrt{10\sqrt{5}}$ 三端均正常：

```html
<msqrt><mn>5</mn></msqrt><mo>+</mo>
<msqrt><mrow><mn>10</mn><msqrt><mn>5</mn></msqrt></mrow></msqrt>
```

不用为了"答案好看"回避嵌套根式。

### 补录题用自定义 key，不影响待录核算

原 PDF 中答案写在详解末尾、无【答案】标记的题会被提取器过滤。
补录时 src 仍按 `M-T-XXX-VN` 编号（如 `M-T-017-V0`）。

这些 key 不在 ref_bank 里，而待录清单是从 ref_bank 生成的，
所以**不会污染核算**。核对时用：

```python
inref = set(k for k in done_keys(bank) if k in r)   # 只算 ref_bank 里真实存在的
# 校验：len(inref) + 重复数 + 待录数 == len(ref_bank)
```

直接用 `len(done_keys(bank))` 会把补录题算进去，导致等式不成立、误判为数据异常。


### 跨专题重复题：保留一道，挂双题型标签

教辅会把同一道题放进两个专题讲解。实测 M-T-016-V1 与 M-T-022-V1 是同一道题
（$\frac{4x^2}{y-1}+\frac{y^2}{2x-1}\geq m$ 恒成立求参数），
分别出现在「因式分解」和「恒成立求参数型」两个专题下。

两题都录进去，孩子按任一专题刷题都会撞见，**等于把一道题做两遍**。

正确做法（正好用上题目⇄题型的多对多结构）：

```
删除其中一道（保留先录入的那道）
保留题的 topics 挂两个：['M-T-016', 'M-T-022']
review 里写明"该题同时出现在两个专题下，只保留一道"
```

这样按 T016 筛能刷到、按 T022 筛也能刷到，但题库里只有一份。

### 核算等式被"既已录又重复"的 key 打破

```
已录 + 重复 + 待录 = len(ref_bank)      ← 校验等式
```

如果某个 key 同时出现在「已录」和「重复」两个集合里，会被计两次，
等式不成立。用这条定位：

```python
both = [k for k in inref if k in dup]    # 非空即说明有题被重复录入
```

第5批就是这样发现的：待录只减了 7 而录入了 8 题，
多出来的那 1 题正是与 T016-V1 重复的 T022-V1。

**核对信号**：本批录入 N 题，待录数应恰好减 N。少了就说明有题撞进了重复集合。

### 数值验证三元二次型最值用特征值

$ab+ac+2bc$ 这类三元二次型在 $a^2+b^2+c^2=10$ 下的最值，
不要用手写的配系数凑（容易算错且难验证），直接走矩阵：

```python
import numpy as np
# ab+ac+2bc = ½·vᵀAv
A = np.array([[0,1,1],[1,0,2],[1,2,0]], float)
ev = sorted(np.linalg.eigvalsh(A))       # [-2, 1-√3, 1+√3]
maximum = 10/2 * ev[-1]                  # 5√3+5 ≈ 13.660
```

Rayleigh 商直接给出结果，还能顺手验证教辅答案。


### LaTeX 导数撇号会截断 raw 单引号字符串

写 `$f'(x)=...$` 时如果用 `r'...'` 单引号包裹，撇号会提前终止字符串：

```python
r'$f'(x)=\frac{1}{x}$'    # SyntaxError: '(' was never closed
r"$f'(x)=\frac{1}{x}$"    # ✓ 用双引号包裹
```

导数符号在一元函数题里到处都是，**一次会坏 7~8 处**。
规则：**凡含 `'` 的 LaTeX 字符串一律用双引号包裹的 raw 串 `r"..."`**。

自检：`python3 -c "import ast;ast.parse(open(f).read())"` 能直接抓到，
写完数据文件先跑一遍。

### 结构检测必须用正则匹配带属性的开标签

对比两端结构数时，写 `html.count('<mtable>')` 恒为 0 ——
渲染出的标签带属性（`<mtable columnspacing="0.6em" ...>`），字面量匹配不到。

```python
re.findall(r'<mtable\b', h)      # ✓
h.count('<mtable>')               # ✗ 永远是 0
```

后果：明明两端一致的项目被报成 `HTML=0 Word=3 ✗`，
**误报会消耗大量排查时间，也会让人逐渐不相信检测结果**。

所有结构对比统一用 `\b` 结尾的正则。

### 一维参数化代替二维扫描，且别在循环里求 max

验算 $\frac{4x+2y}{20x^2+11xy+5y^2}$（约束 $4x^2+y^2+xy=1$）这类题：

1. **先参数化降维**：记 $s=xy$，由约束得 $s\in(0,\frac15]$，
   式子化为 $g(s)=\frac{2\sqrt{1+3s}}{5+6s}$。一维扫描 50 万点毫秒级。
2. **别在循环里调 `max(vals)`**：那是 $O(n^2)$，实测 20 万点直接超时。
   先收集完再求极值。

参数化还有个额外好处：能直接看出教辅答案错在哪。
本题教辅给 $(0,\frac{\sqrt6}{6}]$，参数化后一眼看出下界应为 $g(0)=\frac25$。

### 教辅混淆 t 与 t² 导致区间下界错误

T023-E1 解析写「令 $t=2x+y\in(0,\frac85]$」，
但实际推导得到的是 $(2x+y)^2\leq\frac85$，即 $t^2\in(1,\frac85]$。
把 $t^2$ 的范围当成 $t$ 的范围，下界就从 $\frac25$ 变成了 $0$。

**识别信号**：解析里说「令 $t=...\in(0,A]$」，
而 $A$ 恰好是前面某个平方量的上界时，高度可疑。
遇到区间答案，用参数化扫描核对上下界两端。


### 用解析的"解数特征"反推被提取吃掉的函数符号

复合函数零点题的解析里会明确列出「$t$ 落在某区间时方程有几个解」。
**当提取出的函数形式凑不出题干要求的解数时，用解数特征反推原式。**

本批两例（都是 PDF 提取丢了绝对值）：

| 提取到 | 问题 | 重建为 | 依据 |
|---|---|---|---|
| $\frac{1}{\|x\|}-1$ | $t>0$ 仅 2 解、$t=0$ 无解 → 最多 4 解，凑不出"6 解" | $\left\|\frac{1}{\|x\|}-1\right\|$ | 解析要求 $t=0\to2$ 解、$t\in(0,1)\to4$ 解、$t\geq1\to2$ 解 |
| $\log_{4}x$ | $t\in(1,2)$ 只有 2 解 → 两根最多 4 解，凑不出"6 个" | $\|\log_{4}x\|$ | 解析要求 $t\in(1,2)$ 有 3 解 |

做法：
1. 先按提取形式算一遍解数，与解析逐条对照
2. 找出矛盾点，推测丢失的符号（多半是绝对值）
3. 重建后**回代全部选项验证**——四个选项都要能自洽才可信
4. 在 review 里写清"提取形式、矛盾点、重建依据"

这个反推有硬约束（选项自洽），不是凭空猜。
但若多个形式都自洽，宁可跳过不录。

### 同题不同问：答案矛盾时录有解析的那个

T068-V1（选择，问 $n$ 的可能值，标答"1 或 3"）与
T068-V2（填空，问 $m$ 的集合，标答 $\{3\}$）是同一道题。

按严格计数：两根之积 $-\frac{12}{e^2}<0$，一正一负，
三种情形（正根 $>、=、<$ 极大值 $\frac{6}{e^3}$）解数都是 $1+2$、$2+1$、$3+0$，**恒为 3**。
不存在 1 个解的情形。

V1 无解析可核对，V2 有完整解析。
**录 V2，跳过 V1**，并在 V2 的 review 里写明跳过原因，
否则下次翻清单还会再纠结一遍。

### 数值扫描的三个陷阱（复合零点题专用）

1. **极值切点检测不到** —— $f(x)=t$ 在极值处相切，变号检测失效，
   会把 2 解报成 1 解。极值点要手动判定。
2. **奇点两侧会虚假变号** —— $f(x)=\frac{x}{\ln x}$ 在 $x=1$ 两侧
   从 $-\infty$ 跳到 $+\infty$，扫描直接跨过会产生假交点。
   **必须分段扫描**。
3. **孤立的 t=0 要单独判** —— $\frac{x}{\ln x}=0$ 无解，但扫描容易误报。

正确做法是按单调区间**分段解析判定解数**，
再用它去数二次方程两根的组合，而不是无脑扫描整条曲线。

### $\{3\}$ 集合花括号两端渲染路径不同但结果都对

- HTML：`split_rich`（不经 expand）→ `latex_inline`，
  `latex_inline` 在 464 行显式处理 `\{` `\}` → `<mo>{</mo>`，正体
- Word：`latex_expand` 先 `.replace('\{','{')`，
  再走 OMML → 单个 run `<m:t>{3}</m:t>`，`m:sty="p"` 正体

两端都显示 $\{3\}$ 且都是正体，**不需要修**。

### 中文文本里的 ASCII 双引号会提前终止 Python 字符串

写 `r"…是一个"理想配集"．…"` 时，中文里的直引号 `"` 会提前结束字符串，
报的错还是 `invalid syntax. Perhaps you forgot a comma?`，
指向**下一行**，跟真正的错误位置差一行，极难定位。

排查办法：逐行统计双引号个数的奇偶（注意排除前导反斜杠为奇数的情况）：

```python
for i, line in enumerate(L, 1):
    cnt = 0; j = 0
    while j < len(line):
        if line[j] == '"':
            k = j - 1; n = 0
            while k >= 0 and line[k] == '\\':
                n += 1; k -= 1
            if n % 2 == 0:
                cnt += 1
        j += 1
    if cnt % 2:
        print('L%d 引号不平衡' % i)
```

写题面时中文引号一律用 `“”`，别用 `"`。
已入库的 3 题（M-H0016/21/25）做过一次性批量修复。

### 复合函数零点题：先按单调区间分段解析，别整条扫描

嵌套零点题 `$f(f(x))=0$` 的通用做法：

1. 先求外层 $f(s)=0$ 的全部 $s$（**按分段各算一次**）
2. 对每个 $s$，数 $f(x)=s$ 的解数（按单调区间判）
3. 求和

**每个分段都要单独判定**——$f$ 在 $(-\infty,0]$ 与 $(0,+\infty)$ 上的
单调性、值域往往完全不同。

扫描整条曲线的三个坑：极值切点不变号（漏解）、
奇点两侧虚假变号（多解）、$f(x)=0$ 无解却报有解。
按单调区间**解析判定**比扫描可靠得多。

### 边界特例会让不等式"自动成立"，必须单独列

T073-V2 推到 $s_1(s_1^2-3s_1-1)\leq 0$ 后，若直接"因 $s_1<0$ 故除以 $s_1$ 变号"，
得到 $s_1^2-3s_1-1\geq 0$。但 **$s_1=0$ 时乘积为 $0$，不等式自动成立**，
这一支被"除以 $s_1$"静默丢掉了。

结果就是答案里那个孤立的 "$t=0$"。

**识别信号**：答案形如 "$-4<t\leq\ldots$ **或** $t=0$"，
那个孤立点几乎都是某个不等式的等号特例。
遇到这种答案，回头检查每一步是否有"除以变量"的操作。

### 双函数嵌套：答案常是两种情形的并集

T073-V3 要求 $f$ 图象上存在关于 $y=x$ 对称的两个不同点，
分两种情形：

- 两点都在抛物线段 $\to a\in(\frac12,\frac{\sqrt5-1}{2})$
- 一点在抛物线、一点在射线 $\to a\in[\frac{\sqrt5-1}{2},1)$

并集才是 $(\frac12,1)$。**只算情形二会得到 $[0.618,1)$，与答案不符**。

遇到"存在两点关于 $y=x$ 对称"这类条件，先把图象分段，
枚举两点所属段的全部组合，别默认只有一种。

## 大题只给了第一问详解时，怎么录

教辅专题 3-2（含参讨论）开头明确写了：

> 本专题围绕研究的是讨论点的寻找和训练，故所选大题，解析答案处
> 大多数把第二问暂时去掉。

第 14 批的 7 道题（T096~T097）就是这种情况：【答案】给了两问，
【详解】只有第一个问。

**做法**：只录第 (1) 问，把它当一道完整的解答题。

- 题干 = 函数定义 + 第 (1) 问，**不写第 (2) 问**（写了就是"有问无解"，孩子做了也不知道对错）
- 答案 = 第 (1) 问的结论（分类讨论题的结论是文本，不是单个数值）
- 解析 = 原文【分析】+【详解】合并
- `review` 里注明原书第 (2) 问是什么、答案是什么、为何未录

**为什么可以拆**：给定含参函数、讨论单调性，本身就是一道独立完整的题，
第 (1) 问不依赖第 (2) 问。

**分类讨论题的验算办法**（7 题全部用过，结论与原书一致）：
取若干组参数值，在每个区间内采样 5 个点判导数的符号，
检查是否与结论一致。比整条扫描可靠，因为区间端点不变号。

```python
def chk(name, fp, cases):
    # cases: [(参数值, [(区间左, 区间右, 预期符号)])]
    for p, segs in cases:
        for lo, hi, exp in segs:
            sgn = [1 if fp(x, p) > 1e-12 else -1 for x in 采样点]
            assert (exp > 0 and min(sgn) >= 0) or (exp < 0 and max(sgn) <= 0)
```

**特别注意定义域有洞的情形**：f(x)=e^{ax}/x 的定义域是
(-∞,0)∪(0,+∞)，讨论时必须把两段分开，这是本题最容易漏分的地方。

**书写提醒（本条自己就踩了）**：用 heredoc 往 skill 文档里写 Python 代码块时，
外层定界符会被正文里出现的同类引号提前终止，报的错还指向后面几行。
正文里要提到三引号时，用文字描述或 `write` 工具直接落盘，别写字符本身。
