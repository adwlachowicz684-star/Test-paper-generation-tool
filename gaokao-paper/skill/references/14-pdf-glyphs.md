# 教辅 PDF：符号还原与图题处理

教辅（含《2024高中数学热点题型归纳完整解析版》）用 MathType / PMExtra 字体排公式，
数学符号落在 **Unicode 私用区**，常规 `get_text()` 直接吞掉。
这会让提取出的题干自相矛盾——例如 `f(x)-f(x)=2`（丢了撇号）、`f(x)=x+1` 恒假。

本篇给一套**可复刻的三步法**：还原符号 → 核实存疑 → 处理图题。
配套工具已就位，直接跑命令即可，不需要临时写脚本。

## ★ 首选入口：统一还原器 `tools/restore.py`

**日常录题先跑它**。上下标、分数线、特殊符号一次还原，
`dump_pdf` / `pdf2latex` / `frac_scan` 退居为定位与调试用的专项工具。

```bash
python3 tools/restore.py "$PDF" --page 76                 # 整页
python3 tools/restore.py "$PDF" --page 76 --y0 640 --y1 700  # 限定区域
python3 tools/restore.py "$PDF" --find 'lnx - x + a'      # 按关键词定位页
python3 tools/restore.py "$PDF" --page 0 --stats          # 看字号分布
```

实测输出（页 76，M-T-111-E1 所在页）：

    \frac{lnx - x + a}{x^{2}}              ← 原提取：lnx-x+a / x2
    \frac{x - 2lnx + 1 - 2a}{x^{3}}        ← 原提取：x-2lnx+1-2a / x3

实测输出（页 72，M-T-104）：

    \frac{x - a + 1}{e^{x}}                ← 原提取：x - a + 1 / 2ex
    \frac{(x - a)}{e^{x}}  \frac{e^{x}- 1}{e^{x}}
    \frac{1}{e^{3}}                        ← 原提取：1 / e3

### 三段还原，各管一类破碎

| 破碎类型 | 来源 | 做法 |
|---|---|---|
| 上下标 | 字号/基线被压平 | 字号 < 主字号×0.85；方向用 **bottom** 判 |
| 分数线 | 矢量绘制，文本层没有 | 扫绘图指令的水平线段，按坐标配对分子分母 |
| 特殊符号 | 私用区码位 | GLYPH 表映射（括号/竖线/撇号/根号…） |

### 三个踩过的坑（改代码前先看这里）

1. **判上下标必须用 bottom，不能用 top**。
   实测正文 top=203.83、上标 top=203.86（几乎相等），
   但 bottom 差 3.6 —— 用 top 会全部判反。
2. **分数块必须先全局切，再归行**。
   分子与分母在 PDF 里分属不同视觉行，按行处理每行都看不到完整分数。
3. **主字号只在数学字符里取众数**。
   中英混排时中文与数学字号不同，整行取众数会被中文带偏。

### 已知限制

- **根号**：三段字符合并输出 `√`，但**覆盖范围**无法确定，须人工补
  —— 这是唯一必须人工的部分。
- **嵌套分数**只出内层，外层线找不到完整分母会被跳过，人工一眼可辨。
- 偶有误检（如把短线判成分数线），人工审核时顺手忽略即可。

## 一、还原符号：`tools/dump_pdf.py`

### 用法

```bash
cd /data/workspace/gaokao-paper
PDF=/data/inputs/2024高中数学热点题型归纳完整解析版.pdf

# 1) 按特征词定位题目（最常用，先看这个）
python3 tools/dump_pdf.py "$PDF" --find '有300 个不同的实数根' --context 1200

# 2) 整页还原（题目跨页、或要看一页全貌时）
python3 tools/dump_pdf.py "$PDF" --pages 44 45

# 3) 字符级（判定某个符号到底是圆括号还是方括号时用）
python3 tools/dump_pdf.py "$PDF" --pages 44 --chars --y0 95 --y1 152 --x0 320 --x1 580

# 4) 统计全书私用区码位（换了一本新教辅时先跑这个）
python3 tools/dump_pdf.py "$PDF" --glyphs
```

`--find` 会打印命中处**前后**共约 `--context` 字符，含【答案】【详解】——
详解是校验题干自洽性的唯一依据，一定要一起读。

### 已验证的码位映射

| 码位 | 还原为 | 出现次数 | 说明 |
|---|---|---|---|
| `U+F0EE` | `(` `)` | 29059 | 圆括号，左右同码，按 x 坐标交替判左右 |
| `U+F0F6` | `[` `]` | 2289 | 方括号，同上 |
| `U+F0F4` | `\|` | 4286 | 绝对值竖线 |
| `U+F00A` | `′` | 2291 | 导数撇号 `f′(x)` |
| `U+F001` | `·` | 20278 | 目录点线、填充点 |
| `U+F026` | `‾` | — | 平均值上划线 `ȳ` |

**开闭区间就靠 `U+F0EE` 与 `U+F0F6` 区分。** 这是高频考点：
两个选项内容看着"重复"，实际一个是开区间、一个是闭区间，答案完全不同。

例（页 44 变式 12）：
```
A. (-e - 1/e,-5/2)     ← U+F0EE，开区间
B. [-e - 1/e,-5/2]     ← U+F0F6，闭区间
```

### 还原前后对照

| 场景 | 未还原 | 还原后 |
|---|---|---|
| 导数 | `f(x) - f(x) = 2`（恒假、无解） | `f(x) - f′(x) = 2` |
| 绝对值 | `f(x)=ln(x-1)` | `f(x)=\|ln(x-1)\|` |
| 区间 | 选项 A/B 内容相同 | A 开区间 / B 闭区间 |

### 换行与分数

还原后的文本仍是**按视觉行**排列，分数被拆成上下两行：

```
A. (-e - 1/e,-5/2)   B. [-e-1/e,-5/2]
   e  2                  e  2          ← 分母行单独一行
```

按 `20-latex.md` 还原成 `\frac{1}{e}`、`\frac{5}{2}` 即可。

### 换一本新教辅时

码位映射是**字体相关**的，换书要重跑一次 `--glyphs` 核对：

```bash
python3 tools/dump_pdf.py 新书.pdf --glyphs
```

对表里没有的码位，用 `--chars` 看它**夹住了什么**：
成对出现在表达式两侧的即括号类，紧贴字母右侧且在函数后的即撇号。

## 一之二、自动重建上下标：`tools/pdf2latex.py`

`dump_pdf.py` 只是**把符号显示出来**，结构还得人眼拼。
`pdf2latex.py` 更进一步：用字号与基线**自动算出**上下标，直接吐 LaTeX。

```bash
python3 tools/pdf2latex.py <pdf> --page 11 --scan     # 扫全页，只出含上下标的行
python3 tools/pdf2latex.py <pdf> --page 11 --stats    # 看字体/字号分布
```

### 为什么能这么做

PDF 只存「字符画在哪个坐标、多大」，不存「这是上标」——
**但正文字号与上标字号差得很开**，所以几何信息足够反推：

```
正文 '5'：top=203.83  bottom=213.0   size=7.51
上标 '0'：top=203.86  bottom=209.36  size=4.5
                 ↑ 几乎相同          ↑ 差 3.6
```

### 判方向必须用 bottom，不能用 top

上面那组数据就是坑：**top 几乎相等，bottom 才分得开**。
用 top 判上下标会**全部判反**。代码里取的是 `bbox[3]`。

### 主字号按字体分组取

中英混排时中文与数学字号不同（Word 转的 PDF 实测：中文 10.5、数学 11.99）。
整行取众数会被中文带偏，导致相对数学主字号的上标判不出来。
所以**主字号只在非 CJK 字符里取众数**，中文正文原样输出、不参与判定。

### 两种公式排版都支持

| 来源 | 根号 | 括号 | 上下标 |
|---|---|---|---|
| MathType（教辅原书） | U+F0E8/E9/EA 三段拼 | U+F0EE 私用区 | 5.40 / 9.01 |
| Word、LibreOffice | U+221A 标准字符 | 标准字符 | 7.2 / 11.99 |

两家都会丢语义结构，但几何判据对两者都成立。
Word 转的 PDF 跑出来更干净（根号直接是 `√`，见下）。

### 实测效果（第 13 批 20 个上下标）

```
✅ 自动命中    13 个（65%）
⚠️ 未覆盖       7 个
   ├─ 5 个是分数/根号   ← 矢量绘制，文本层里真没有，人工补
   └─ 2 个是嵌套下标    ← 字符都在，只是分组被摊平，人工重新套一层
```

**结论：上下标能自动搞定，分数和根号必须人工补。**
这正是"人工审核不可省"的精确边界——不是所有活都得人干。

### Word 转的 PDF 也能跑

同一批题，Word 转出 PDF 后跑 `--scan`：

```
1．设 a=log4，b=log4，c=0.5^{−0.2}，则 a,b,c 的大小关系是（　　）
3．若 a=2^{0.3}，b=log0.3，c=0.3^{2}，d=log2 …
5．已知 a=√3，b=2^{¿34}，c=loge …      ← √ 直接就是标准字符
```

`¿` 是 OpenSymbol 的分数线占位，按上下文补成 `2^{\frac34}` 即可。

## 一之三、分数线自动扫描（frac_scan.py）

分数线是**矢量绘制**的，文本层里没有；但它在**绘图指令**里是一条
「高度≈0、宽度几 pt」的水平线段，可以扫出来再按坐标配对分子分母：

```bash
python3 tools/frac_scan.py <pdf> --page 76              # 扫一页
python3 tools/frac_scan.py <pdf> --find 'lnx - x + a'   # 按关键词定位
python3 tools/frac_scan.py <pdf> --page 76 --context 3  # 带上下文原文
```

实测输出（PDF 页 76）：

    \frac{1 + x}{ex}                  → \frac{1+x}{\mathrm e^x}
    \frac{lnx - x + a}{x2}            → \frac{\ln x-x+a}{x^2}
    \frac{x - 2lnx + 1 - 2a}{x3}      → \frac{x-2\ln x+1-2a}{x^3}

**注意**：上标显示为平文本（`x2` 实为 $x^2$），需与 pdf2latex.py 的字号判据
配合使用；根号不是线段（是 U+F0E8/E9/EA 三段字符），本脚本不管。

判据：分数线 = 绘图指令中 `height < 0.5` 且宽度在 `--minw/--maxw` 之间的
水平线段；分子/分母取**数学字体**字符（中文正文按字体名排除），
中心 x 落在线段范围内、底边/顶边紧贴线。

## 二、核实存疑题

遇到"看不懂""答案对不上""选项重复"的题，按下表逐条核实，
**核实完再决定录不录**。实测本批次 3 道"存疑"题全部核实通过、一道没丢。

| 存疑类型 | 核实动作 |
|---|---|
| 选项看着重复 | `--chars` 看括号码位，判断是开闭区间之别 |
| 答案与自算不符 | 重算一遍；**优先怀疑自己的分支漏了** |
| 方程恒真/恒假 | 十有八九丢了撇号或竖线，看 `--chars` |
| 纯图解题 | 走第三节切图流程，图能切就能录 |

**自算与标答不符时，先怀疑自己。** 实测案例：算某题上限应为 `9/4`，
怀疑原书印错；重算后发现是漏了 `u₂=5/4` 这一支，
补上后正好撑起标答中 `(-5/2,-9/4)` 那一段——原书无误。

核实结论写进 `review` 字段，把推理链留下来：

```python
'review': (
    r"★ 曾误判此答案偏大（以为上界应为 $\frac{9}{4}$），"
    r"独立验算后发现是漏了情形二：$u_{2}=\frac{5}{4}$ 时 "
    r"$f(x)=\frac{5}{4}$ 有 $2$ 个解，补上后与标答 A 完全吻合，原书无误。"
),
```

## 三、图题切图：`tools/cut_figs.py`

图题以前只能跳过。现在切图→入库→三端渲染整条链路已跑通（网页 / HTML / Word 均验证过）。

### 三步走

```bash
PDF=/data/inputs/2024高中数学热点题型归纳完整解析版.pdf

# 1) 列出该页所有图及位置（页码是 0-based）
python3 tools/cut_figs.py "$PDF" --list 45

# 2) 校验候选框（确认没切进邻题）
python3 tools/cut_figs.py "$PDF" --check 45 --boxes 332,491,442,601 457,493,557,601

# 3) 切图，文件名用题目 ID
python3 tools/cut_figs.py "$PDF" --cut 45 --qid M-H0190 \
    --boxes 332,491,442,601 457,493,557,601
```

`--list` 输出示例（页 45 右栏两张并排图）：

```
  #3  xref=262  原始 208x217  位置 (334,492)-(440,602)  → --boxes 334,493,440,603
  #4  xref=265  原始 208x234  位置 (458,494)-(555,602)  → --boxes 459,495,555,603
```

直接把 `--boxes` 后面的数字抄给 `--check` / `--cut` 即可。

### 校验判据

脚本看的是**框内**有没有邻题文字：

- 框内无文字 → 纯曲线图，安全
- 框内只有 `O` `x` `y` 或数字 → 坐标轴标注，正常
- 框内有中文正文 → 切歪了，收窄该框

框外紧贴着 `A. 1 / B. 2` 这类选项属正常（题目排版本就如此），只作提示不报错。

### 命名与存放

切出的图落在 `src/slices/数学/{题目ID}_fig{n}.png`，如 `M-H0190_fig1.png`。
三端都按 `{ID}_fig{n}` 在 `src/slices/<科目>/` 下找，**文件名不能自定**。

### 填入题目

`--cut` 会直接打印可粘贴的 figs 列表：

```python

```

# 预估：当前最大 M-H 号 + 本批内序号

## 四、完整流程（一批图题+文字题混排）

```
1. dump          tools/dump_pdf.py --find '特征词'      ← 还原符号后的原文
2. 读详解        用【详解】反推题干自洽（见 21-review-rules.md）
3. 存疑核实      按第二节逐条核实，不轻易跳过
4. 图题切图      tools/cut_figs.py --list / --check / --cut
5. 写入脚本      tools/input_batchNN.py（含 figs 字段）
6. 入库          tools/commit_batchNN.py
7. 导出核对      export-html / export-docx + tools/check_render.py
8. 回归          selftest.py + test.mjs + check_skill_docs.py
```

第 4 步只对图题做，其余题跳过。
