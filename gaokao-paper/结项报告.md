## 三、质量保障：四道防线

题库不是录入完就结束，而是每层都有校验。

### 3.1 入库前校验

| 环节 | 内容 |
|---|---|
| `lint_input.py` | 录入脚本语法检查，拦截跨行字符串与未闭合 `$` |
| `lint_math.py` | 全库公式扫描，查 LaTeX 命令合法性、括号配对、越界值 |

这两道拦截了绝大多数问题。整个项目中，**跨行字符串是最高频的坑**（累计触发 20 余次），后期改为脚本自动归并后才彻底解决。

### 3.2 入库后回归

| 测试 | 结果 |
|---|---:|
| 后端回归 | **454 / 454** |
| 前端回归 | **37 / 37** |
| 文档自检 | **109 / 109** |
| 公式扫描 | 严重 **0**、轻微 7 |

轻微 7 项均为公式内含中文标点或中文下标（如 `V_{球}`、`V_{柱}`），**不影响渲染与阅读**，属可接受的排版习惯，故保留。

### 3.3 两端核对

每批录入后，本地 `bank.json` 与远端仓库逐题比对，确认题数、编号、内容一致。**累计核对 130 批，零不一致。**

### 3.4 人工复核

这是自动检测替代不了的一层。凡出现"算出来矛盾"的，一律反推原文：

- 模长算出负数 → 根号丢失
- 正弦值大于 1 → 根号丢失
- 点到平面距离大于该点到平面上已知点的距离 → 答案错误
- 离心率 $e>1$ 用在椭圆上 → 根号丢失
- 代入 $n=1$ 与逐项求和不符 → 指数上标丢失

这条"数学指纹"判据贯穿全程，也是后面勘误发现的来源。

## 四、最有价值的产出：发现原书问题

录入不是誊抄。全书共识别并修正 **119 条记录 / 117 道独立题**，分四类：

| 类别 | 含义 | 数量 |
|---|---|---:|
| **A 类** | 原书**答案本身有误**，已按正确答案录入 | **19** |
| **B 类** | PDF 提取丢符号（原书无错），已还原 | **88** |
| **C 类** | 答案对，但详解/选项有笔误，已修正 | **11** |
| **D 类** | 存疑但证据不足，按原书录入并留痕 | **1** |

### 4.1 A 类：真正发现原书印错（19 题，最不可替代）

举三例说明判断依据的严谨程度：

**① M-H0220：四个命题全真，原书判②为假是用反了不等号**

② 断言 $\ln\pi < \dfrac{\pi}{\mathrm e}$。由 $\dfrac{\ln x}{x}\le\dfrac1{\mathrm e}$（$x=\mathrm e$ 取等），$\pi\ne\mathrm e$ 故严格小于。原书据"$\mathrm e<\pi$ 且 $f$ 递减得 $f(\mathrm e)>f(\pi)$"判②假——**递减关系是 $x>\mathrm e$ 才成立，$\pi$ 在递减区间内应得 $f(\pi)<f(\mathrm e)$**，方向用反了。

数值佐证：$\ln\pi = 1.144729886 < \dfrac{\pi}{\mathrm e} = 1.155727350$。

**② M-H1311：7 种结果被当成等可能**

原书取 $P(\xi=2)=P(\xi=3)=\dfrac37$。但这 7 种结果分属 2/3/4 次投掷，概率分别是 $\dfrac19$、$\dfrac1{27}$、$\dfrac1{81}$，**并不等可能**。按条件概率归一化得 $\dfrac{27}{37},\dfrac9{37},\dfrac1{37}$，故 $E\xi=\dfrac{85}{37}\approx2.297$（原书 $\dfrac{19}7\approx2.714$）。

**③ M-H0802 区间端点：`(-3/2, 3]` 应为 `[-3/2, 3]`**

$x=0$ 在定义域内、$-\dfrac32$ 取得到，左端应闭。原字段误作圆括号。

### 4.2 B 类：提取造成的"假错误"（88 题，占比最大）

教辅用 MathType/PMExtra 字体排公式，数学符号落在 Unicode 私用区，常规提取会吞掉。典型表现：

| 丢失内容 | 表现 | 判据 |
|---|---|---|
| 根号 | `3/2` 实为 $\dfrac{\sqrt3}2$ | $e>1$ 对椭圆无意义 |
| 指数上标 | `2n` 实为 $2^{n+1}$ | 代 $n=1$ 与逐项求和不符 |
| 方括号 | `-2,2` 实为 $[-2,2]$ | 区间缺括号 |
| 分母结构 | 分式被读成乘法 | 代入后与详解中间量不符 |

**这类不是原书印错，而是数字化过程必然产生的噪声**——正因为有这 88 题的还原经验，才逐步总结出可复用的判据模板。

### 4.3 一处特殊裁定：M-H0252（D 类唯一留存）

方程 $2\{x\}=1+\dfrac1x$，原书按"有限个零点"处理。实际零点集可完全解出：

$$\{-1\}\cup\{\pm x_n:n=1,2,3,\cdots\},\qquad x_n=\frac{(2n+1)+\sqrt{(2n+1)^2+8}}{4}\in(n,n+1)$$

配对**有严格代数证明**：若 $x\in(n,n+1)$ 是零点，取 $y=-x\in(-n-1,-n)$，则 $\{y\}=n+1-x$，代入可验 $y$ 也是零点。$x=-1$ 落单，是因为其对称位置 $x=1$ 处 $\{1\}=0$ 而 $1+\frac11=2\ne0$——**对称性在整数点跳跃处失效**。

结论：零点无穷多，$x_n\sim n+\dfrac12$。"所有零点之和"作为级数发散、无严格定义，这是**命题瑕疵而非答案错误**。故留 D 类，答案维持原书。

### 4.4 修正标记：方便后期验证

全部 143 题带结构化 `fix` 字段（A19/B86/C11/D1/**E26**），可按 `fix.cls` 检索：

- E 类是本轮新增的**录入与排版修正**类（如 `$$` 未闭合、字面 `\n` 未还原、错码 `\x07ngle` 顶替了 `\angle`）
- 标记与勘误表同源，重跑 `tools/build_fix_registry.py` 即全量刷新，不会两处漂移
- 明细见《已修正题目清单.md》

## 六、方法与经验

### 6.1 选题策略：从"题型优先"改为"页码聚堆"

早期按题型筛选题目，同一页上属于其他题型的题会被永久排除，导致 **14 题要跨 7 页**，读原文来回翻。

改为以**页**为单位贪心：进入题最多的页，取完该页主堆后顺手取走同页其他堆（页已打开，边际成本几乎为零）。跨页数从 7 降到 4。

### 6.2 定位方法：从"12 字锚点"改为"8 字滑动窗口投票"

剩余题的题干普遍缺根号、数字粘连，12 字精确锚点匹配率一度降到 **0**。

改用"题干多个 8 字片段分别搜索、按命中页投票"，成功率回升到 24/28。**顺带发现此前报的页码有系统性偏差**——例如某题工具标 p075，实际在 p126。

### 6.3 查重：三道防线

全书同一题在不同页重复出现、被编不同型号的情况**发生过 4 次**（M-T-260-V1 / M-T-319-V1 / M-T-326-V1 等）。根因是按 `M-T-xxx-Vn` 匹配 `src`，跨编号查不到。

现在的做法：录入前先跑相似度查重 + 人工比对题干数据 + 答案一致性核验。

### 6.4 不硬凑原则

宁可少录，也不往题库里塞不确定还原。全项目主动登记放弃 65 条（含重复 15 条），原因分布：

| 原因 | 数量 |
|---|---:|
| 提取破碎 | 31 |
| 重复 | 15 |
| 答案存疑 | 11 |
| 待核查 | 3 |
| 印刷错误 | 3 |
| 解析截断 | 2 |

这些题的 `stem_raw` 与判定理由全部留档，人工拿到纸质书可快速复核。

## 九、结语

从 457 页 PDF 到 1364 道结构化题目，这个项目真正的难点**不在录入速度，而在判断可靠性**：

- 怎么确认一个被 OCR 吞掉根号的答案，还原后是对的？（用数学指纹反推）
- 怎么区分"原书印错"和"提取出错"？（A 类 vs B 类，判据完全不同）
- 什么时候该停下来不录？（不硬凑原则）

这三件事贯穿 130 批，也沉淀成了可复用的判据模板。最终交付的不只是 1364 道题，还有**一套能自我校验的题库维护机制**——这才是后面能长期用下去的部分。
