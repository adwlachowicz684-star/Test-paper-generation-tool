# 高考组卷 · Tauri 2.0 桌面应用

把「真题 PDF → 拆题入库 → 自动组卷 → 在线练习 → 间隔复习」整条链路
封装成一个桌面应用。

**核心升级：消灭「手工登记」这个最大失败点。**
孩子在应用里点选答案 → 自动判分 → 自动写练习记录 → 自动算下次复习日。
不需要家长批改、不需要填 Excel。

## 四、架构决策与理由

### 1. 前端为什么不用 React/Vue

零构建。没有 Vite 就没有打包环节，出问题的地方少一半。
试卷 CSS 是从已经验证过的 `build_html.py` 直接搬过来的，
保证「屏幕预览」和「打印输出」完全一致。

### 2. 公式为什么用 MathML 而不是 KaTeX

| | MathML | KaTeX |
|---|---|---|
| 依赖 | 浏览器原生，零依赖 | 需加载 JS + CSS + 字体 |
| 离线 | 可用 | 需打包资源或 CDN |
| 打印 | 矢量，清晰 | 依赖字体加载 |

`mathml.py` 与前端 `render.js` 里的转换逻辑是同源的，
改一处记得同步改另一处。

### 3. 业务逻辑为什么留在 Python

PDF 拆题涉及大量正则、几何坐标计算、栏位聚类，
这些代码已经过 12 份真题、216 道题验证。
用 Rust 重写一遍不仅工作量大，还会引入新的 bug。

Rust 只负责：进程调度、数据透传、路径管理、原生对话框。

**接口**：`python py/main.py <cmd> --args` → stdout 输出一行 JSON。
两边彻底解耦，Python 侧可独立调试。

### 4. 数据存在哪里

| 数据 | 位置 | 丢失风险 |
|---|---|---|
| 题库 | `data/bank.json` | 可重建（重跑拆题） |
| 练习记录 | `data/progress.json` | **不可重建** |
| 切图 | `slices/` | 可重建 |

**练习记录是整个系统唯一无法重建的数据。**
换电脑、清缓存、重装系统都会丢，且是一个学期的错题历史。

应用内「复习计划」页有一键备份，导出 `progress_backup.json`，
建议每周备份一次放到网盘。

## 六、记忆曲线规则

| 情况 | 复习等级 | 间隔 |
|---|---|---|
| 连续错 2 次以上 | -2 | 1 天 |
| 错 1 次 | -1 | 2 天 |
| 未练习 | 0 | — |
| 做对 1 次 | 1 | 7 天 |
| 连续做对 2 次 | 2 | 15 天 |
| 连续做对 3 次 | 3 | 30 天 |
| 连续做对 4 次 | 4 | 60 天 |
| 连续做对 5 次 | 5 | 120 天 |

任何一次做错 → 退回最低档重爬。

**为什么首次是 2 天而不是 7 天**：刚做错时对「自己当时怎么想的」记得最清，
此时重做才是改思路；拖到 7 天，多数人只记得答案、忘了错因，变成背答案。

规则定义在 `py/main.py` 的 `LADDER`，改一处即全库生效。


### 题号独立左列（悬挂缩进）

**需求**：试卷题号显示在题目左侧、单独显示，扫题时一眼定位。

**原实现**：题号内联在题干文本流里
```html
<span class="qnum">1．</span>定义在 R 上的奇函数 f(x) 满足...
```
题号淹没在正文中，找第 N 题要逐行读。

**新实现**：题号独占一列，其余内容整体右移。

| 端 | 实现 |
|---|---|
| HTML | `.q` 用 `display:grid`，两列；`.qnum` 设 `grid-column:1` + `grid-row:1/-1`（跨所有行），右对齐贴近题干 |
| Word | 题干段落**悬挂缩进** `left_indent=0.85cm` + `first_line_indent=-0.85cm` |
| 前端练习页 | 同 HTML（styles.css 里 `.paper .q`） |

悬挂缩进是试卷的标准排法：题号左凸出，**题干换行后与题干首行对齐**，
不会跑到题号下面。

**关键坑**：grid 布局下**裸文本节点会被匿名包裹成 grid item**，
可能串进第 1 列。所以题干/选项/插图/留白**必须各自包在容器里**：

```python
# 错：题号与题干连成一个字符串
body.append(f'<span class="qnum">{n}．</span>' + _rich_html(stem))

# 对：题号独立元素，题干包 <div>
body.append(f'<span class="qnum">{n}．</span>')
body.append('<div>' + _rich_html(stem) + '</div>')
```

**缩进要跟着走的内容**：

| 内容 | 处理 |
|---|---|
| 题干 | `hang_indent()`（悬挂） |
| 选项表格 | `table_indent()` 写 `w:tblInd` |
| 插图 / 图注 | `body_indent()` |
| 解答题留白 | `body_indent()` |
| 答案卷的答案/来源/解析 | 答案行悬挂，来源/解析 body_indent |

**第二个坑**：带图题的选项在**外层表格的 cell 里**
（`doc.add_table(1,2)` → cell(0,0) 放选项）。
外层表格已整体缩进，cell 里的选项表格再缩进一次会**双倍偏移**。
所以用 `isinstance(container, _Cell)` 判断：cell 里不缩进。

**配置**：`paper_template.QNUM`

```python
QNUM = {
    "hang_cm": 0.85,
    "color": (0x1F, 0x38, 0x64),   # 与答案卷同色
    "bold": True,
    "html_min_em": 2.4,
}
```

**验证**：不能只看题号数字，要查缩进是否真的写进 XML：

```python
# Word
'<w:ind w:left="482" w:hanging="482"/>' in p._p.xml   # 482 twips = 0.85cm
'<w:tblInd w:w="482" w:type="dxa"/>' in t._tbl.xml
# HTML
html.startswith('<div class="q"><span class="qnum">1．</span><div>')
```

已加 8 条回归用例（题号独立元素、三种题型内容包容器、
CSS 声明两列、Word 悬挂缩进、题号配色）。

### 选项分列：按渲染宽度，不按源码字符数

**现象**：第 6 题（四个分数选项）、第 8 题（`$f(-\frac12)=0$` 等）
明明排得下一行，却被降成 2 列甚至 1 列。

**根因**：分列依据是**源码字符数**，但公式渲染后视觉宽度完全不同。

`\dfrac{4}{3}` 源码 13 字符，渲染成上下堆叠的分数后**只有约 1.4 字符宽**。

**两端错法还不一样**：

| 端 | 错误 |
|---|---|
| Word | 正则 `\\(frac\|sqrt)\{...` **不认 `\dfrac`**，于是按源码算成 15 字符 → 2 列；第 8 题 33 字符 → 1 列 |
| HTML | 认 `\dfrac`，但统一乘 1.5 系数——**方向反了**，分数应缩小不是放大 |

注意这两个错误的方向相反：早期为了修"选项被裁切"把 `\frac` 换成 `'xx'`（估太短），
后来改成算源码长度（估太长）。两次都没抓住本质。

**修法**：`paper_template.render_width()` 递归解析 LaTeX，按视觉宽度算：

| 结构 | 宽度 |
|---|---|
| `\frac{a}{b}` | `max(w(a), w(b)) + 0.4` ← **上下堆叠，取较长边** |
| `\sqrt[n]{x}` | `w(x) + 0.8` |
| `x^{n}` / `x_{n}` | `w(x) + 0.65 * w(n)` |
| 函数名 `\sin` `\log` | 按名字长度 × 0.9 |
| `\left` `\right` `\!` | 0 |
| 中日韩字符 | 2 |

**容量依据**（A4，BODY_W=16.2cm，10.5pt，半角字符≈0.185cm）：

| 列数 | 每列可容纳 | 当前阈值 |
|---|---|---|
| 4 列 | ≈ 19.9 | 8 |
| 2 列 | ≈ 41.7 | 26 |

阈值比容量留了很大余量，偏保守。要放宽就调 `OPTIONS["col_rules"]`，
但不要超过 `col_capacity(cols)` 的返回值。

**验证**：已加 9 条用例，含"估算宽度不得超过该列数的容量"——
这才是真正要防的（溢出/裁切），列数本身不是关键。

修复后两端列数完全一致：第 6、8、9 题从 2/1 列回到 4 列。

### 数学正体/斜体：不能依赖浏览器默认

**现象**：区间 `(0,1)` 整体显示为斜体。

**背景**：MathML 规范里 `<mn>`（数字）、`<mo>`（运算符）该是正体，
`<mi>`（标识符/变量）该是斜体。但**各浏览器实现不一致**，
Chrome 对 `<mo>` 的处理就可能不是正体。

**修法**：CSS 里显式写死，不赌浏览器默认：

```css
math mi{ font-style:italic; }                    /* 变量 → 斜体 */
math mn, math mo, math mtext{ font-style:normal; } /* 数字/括号/运算符 → 正体 */
math mi[mathvariant="normal"]{ font-style:normal; } /* 函数名、数集 → 正体 */
```

**同时**，非变量的 `<mi>` 要输出 `mathvariant="normal"`：

| 内容 | 输出 | 理由 |
|---|---|---|
| `\mathbb{R}`（数集） | `<mi mathvariant="normal">R</mi>` | 斜体 R 会被当成普通变量 |
| `\log` `\sin` `\max` | `<mi mathvariant="normal">log</mi>` | 函数名固定正体 |
| `x` `f`（变量） | `<mi>x</mi>` | 变量保持斜体，符合数学规范 |

**顺带修的 bug**：函数名原来要求后面紧跟 `([{` 才整体输出，
于是单独的 `$\max$`、`$\ln$` 被拆成 `m`·`a`·`x` 三个斜体字母。
改为只要整词是函数名就整体正体输出。

Word 端无此问题：OMML 默认不带 `<m:i/>`，全为正体。

### HTML 题号布局：不用 grid-row 跨行

**现象**：题目内容全挤到页面右侧。

**根因**：`.qnum` 用了 `grid-row: 1 / -1` 想让题号跨所有行。

**`-1` 指向的是「显式网格」的最后一条线**。而 `.q` 没有定义
`grid-template-rows`（行是隐式生成的），于是 `-1` 并不能覆盖所有行 ——
题号之后的内容会流回第 1 列，整块被挤向右侧。

**修法**：改成嵌套容器，`.q` 只有两个 grid item：

```html
<div class="q">
  <div class="qnum">1．</div>
  <div class="qmain">        ← 题干/选项/插图/留白全在这里，内部流式排布
    <div>题干...</div>
    <div class="opts">...</div>
  </div>
</div>
```

```css
.q{ display:grid; grid-template-columns:2.4em 1fr; column-gap:4pt; }
.qmain{ min-width:0; }       /* 允许收缩，防撑破列宽 */
```

这样内容在 `.qmain` 内部怎么排都不会跑到题号列，
也彻底回避了 `grid-row:-1` 在隐式网格下的不确定性。

两端（`build_html.py` 与前端 `render.js`）已同步。

### HTML 屏幕预览：A4 尺寸

**现象**：屏幕上的页面不像 A4，且与打印结果不一致。

**根因**：`.paper` 的 padding 是 `16mm 14mm`，而 `@page` 的页边距是
`22mm 24mm` —— 两者不符，屏幕内容宽度（134mm）≠ 打印内容宽度（162mm）。

**修法**：屏幕预览把 `.paper` 做成一张 A4 纸，padding **直接用 @page 的页边距**：

```css
@media screen{
  .paper{ width:210mm; min-height:297mm;
          padding:22mm 24mm;      /* 与 @page margin 相同 */
          margin:0 auto; background:#fff; box-shadow:...; }
}
@media print{
  /* 打印时页边距交给 @page，.paper 必须归零 ——
     否则多页文档第 2 页起会叠加（padding 只在整个元素首尾） */
  .paper{ width:auto; min-height:0; padding:0; box-shadow:none; }
}
```

打印时若 `.paper` 仍带 padding，多页文档的第 2 页起会多出一次内边距，
与首页不齐。所以打印必须归零。

### Word 端区间/函数名是斜体：OMML 必须显式写 `<m:sty>`

**现象**：docx 里 `(0,1)` 整体斜体。

**根因（最隐蔽的一个）**：**OMML 数学区里 `<m:t>` 的默认字体就是斜体**，
即使 run 里**没有** `<m:i/>` 也一样。

```xml
<!-- 看不出任何斜体标记，Word 仍渲染成斜体 -->
<m:r><m:rPr><m:rFonts m:ascii="Cambria Math"/></m:rPr><m:t>(0,1)</m:t></m:r>
```

从 XML 上完全看不出问题 —— 没有斜体标记却渲染成斜体，排查时会误以为是别的原因。

**修法**：每个 run 都显式写 `<m:sty>`，正体 `m:val="p"`，斜体 `m:val="i"`，
**两者都不能省略**。

### f(x) 的 f 是斜体：单字母函数名

**现象**：HTML 里 `f(x)` 的 f 显示为斜体。

**规则**（数学排版规范 ISO 80000-2）：函数名正体、变量斜体。
`f(x)` 里的 f 是**函数名**，不是变量。

判定：**单个字母 + 后面跟着左括号** → 函数名 → 正体。
多字母且不在函数名表里（如 `abc(d)`）→ 视为变量相乘 → 斜体。

**必须跳过间距命令**：``f\!\left(x\right)`` 里 f 后面先是 ``\!`` 再是 ``\left``，
不跳过就会漏判，`f` 被当成变量（斜体）。

三端（HTML `latex_inline` / Word `omml_latex` / 前端 `render.js`）
共用同一套判定，已加锁死用例。

### 顺带修：`\log_{\frac{1}{2}}` 被切成 lo ᵍ

`merge_script()` 取上下标基底时只取**末尾单个字符**，
于是 `\log_{...}` 的基底被当成 `g`，剩下 `lo` 当文本 ——
页面上显示成 **lo ᵍ**，完全读不通。

改为**优先匹配函数名**（`FUNCS` 里的整词），匹配不到才退回单字符。

### 顺带修：前端 `$f(x)$` 不渲染

前端 `rich()` 判断"有没有公式"时**漏了 `L` 段**（`$...$` 通用 LaTeX），
于是 `$f(x)$` 这种不含 `\frac/\sqrt/上下标` 的公式走了 `esc()`，
练习页上孩子看到的是 **`$f(x)$` 源码**而不是 f(x)。

补 `L` 到判断条件与渲染分支。

**统一的效果**：

| 内容 | 字体 |
|---|---|
| `f(x)` 的 f、g、h | 正体 |
| `\log` `\sin` `\max` | 正体 |
| `\mathbb{R}` `\mathbb{N}` | 正体 |
| `(0,1)` `-1` `+` | 正体 |
| `x` `y` `n` `a` `m` | **斜体**（变量） |

两端一致：HTML 用 `<mi mathvariant="normal">` + CSS `font-style`，
Word 用 `<m:sty m:val="p"/>`。

### 人工录入 2022 新高考I卷 暴露的三个 bug

录入 7 道题（第 1/2/3/5/6/7/9 题）后逐题比对两端渲染，
抓到三个只有"真的录进去才看得见"的问题：

**① `90^\circ` 渲染成 `90^\ c i r c`**

`_read_arg`（HTML 端）/ `readArg`（前端）对非 `{` 参数**只取单个字符**，
于是 `^\circ` 的上标取到 `\`，剩下的 `circ` 被当成变量 c·i·r·c 逐个输出。

```
<msup><mn>90</mn><mrow><mo>\</mo></mrow></msup><mi>c</mi><mi>i</mi><mi>r</mi><mi>c</mi>
```

页面显示 **90^\ c i r c**，完全乱排。

新增 `_read_script_arg` / `readScriptArg`，三种形式：`{..}` 取组内、
`\cmd` 取整条命令、其他取单字符。

**② 连续下标只有最后一个生效**

```python
t = re.sub(r'_([0-9a-zA-Z])(?![{a-zA-Z0-9])', r'_{\1}', t)
```

负向前瞻要求下标字符后面**不能**跟字母数字。于是：

```
ABCD-A_1B_1C_1D_1
  A_1 后面是 B → 前瞻失败
  B_1 后面是 C → 失败
  C_1 后面是 D → 失败
  D_1 后面是结尾 → 只有它展开
```

Word 里显示成 **ABCD-A _1B _1C _1D₁**——前三个下标变成字面量 `_1`。
正方体、棱柱、多变量题（`x_1+x_2`）全中招。

按 LaTeX 规则 `_` 只作用于下一个 token，所以直接去掉负向前瞻即可，
并扩展为支持命令：`_(\\[a-zA-Z]+|[^{\s])`。

**③ 数字串基底被切成一个字符**

`merge_script` 取上下标基底时只取末尾单字符，
`90^{\circ}` 的基底变成 `0`，剩下 `9` 当文本——Word 里显示 **9 0°**，
度数符号跑到了 0 头上。

改为按优先级取：函数名整词 → **连续数字串** → 单个字符。

### 向量 / 上划线 / 粗体：源码整段泄漏

**现象**（用户反馈）：第 3 题显示「记 `overrightarrow{CA}=boldsymbol{m}`」，
HTML 与 Word 都有。

**根因**：`\overrightarrow`、`\vec`、`\overline`、`\boldsymbol`
四个命令**不在符号表里**，走了「未知宏」分支，输出命令名本身：

```html
<mrow><mi>overrightarrow</mi><mrow><mi>C</mi><mi>A</mi></mrow></mrow>
```

页面显示 `overrightarrowCA`，完全读不通。这四个是中学数学的高频记号
（向量、共轭复数、粗体向量），缺了影响很大。

**修法**（三端）：

| 命令 | HTML (MathML) | Word (OMML) |
|---|---|---|
| `\overrightarrow` | `<mover accent="true">` + `→` | `<m:acc><m:chr m:val="→"/>` |
| `\overleftarrow` | 同上 + `←` | 同上 |
| `\vec` | 同上 + `⃗`（组合箭头） | 同上 |
| `\overline` | 同上 + `¯` | `<m:bar><m:pos m:val="top"/>` |
| `\boldsymbol` | `<mstyle mathvariant="bold">` | run 里加 `<m:b/>` |

**Word 端要特别处理**：`latex_expand` 的 `_KEEP` 必须保留这些命令的反斜杠，
否则它们会在展开阶段变成普通文本，后续 `split_rich` 拿不到结构。
同时 `split_rich` 要产出 `V`/`O`/`H`/`B` 段，`omml_segs` 才有的渲染。

**踩坑**：`split_rich` 与 `split_frac` 里都有 `rac` 分支，
用 `replace(..., 1)` 加代码会插错函数。
（`_minner` 与 `omml_segs` 也都有 `\sqrt` 分支，同理。）

**不支持 `\underline`**：命令名里的下划线会与「补花括号」正则冲突
（`_u` 被当下标），而它在 K12 数学中几乎用不到，得不偿失。

### 第一批审核反馈：六个渲染问题（用户逐个发现）

**① `\mid` 显示成 `mid`** —— 集合描述法的分隔符。
连同 `\subsetneq` `\supsetneq` `\complement` `\setminus`
**五个符号全不在 MACRO 里**，页面直接输出命令名。

根因值得记：之前录的都是函数、三角函数、向量题，用不到集合符号。

**② `\{1,2\}` 显示成斜体花括号** —— 转义花括号走"未知宏"分支
输出 `<mi>{</mi>`，而 `<mi>` 默认斜体。改为显式 `<mo>{</mo>`。
Word 端则是反斜杠没去掉，显示 `\{1,2\}`。

**③ 填空下划线泄漏 `\underline{\hspace{2em}}`** —— 三端都不支持
`\underline`（命令名里的下划线与"补花括号"正则冲突）。
改为录入时直接写 `____`，patterns 里也加了兜底识别。
已迁移 14 题的 stem / stem_text / answer / solution / opts。

**④ `\complement_U A` 的下标 U 消失且不报错** —— `∁`(U+2201)
不是字母、数字、括号、函数名，基底提取的五条规则前四条全落空，
段停在 `('x', sub, sup)` 状态，渲染层没有 `x` 分支 → **静默丢弃**。
新增第 5 条兜底：紧邻的单个非空白字符做基底。

**⑤ `\par` 显示成源码** —— LaTeX 分段命令，三端不支持。
改为中文标点分句。

**⑥ 分段函数大括号显得特别大** —— mtable 默认行距较松，
stretchy 的 `{` 被撑高。加 `rowspacing="0.15ex"` 收紧。
（这一条需用户确认效果。）

**另修：迁移只改了 stem_text，漏了 stem 列表** ——
`_prep_fields` 会用 `' '.join(stem)` 覆盖 stem_text，
脏的 stem 会把干净的 stem_text 覆盖回去。两边都要清。

### 本轮踩的三个自己的坑

1. **Python 字符串里 `\b` 是退格符** —— 写 JS 注释时用普通三引号，
   结果文件里写入 `\x08`，后续 replace 全部匹配不上。LaTeX 字符串一律用 raw。
2. **assert 失败导致文件没保存** —— `replace` 在前、`assert` 在中、
   `write` 在后，断言一失败前面的改动全丢，且"没报错地跑完"。
3. **统计口径不一致误报** —— 一端只算 stem、另一端算 stem+opts，
   下标数对不上，白排查一轮。

## 六之三、公式渲染的两个坑

### 1. 参数必须递归解析

`\frac{\sqrt{3}}{2}` 的分子本身是个根号。若参数不递归，
`\sqrt{3}` 会被逐字符拆成 `<mo>\</mo><mi>sqrt</mi><mo>{</mo>…`，
**屏幕上就显示成源码文本 `\sqrt{3}`**。

三处渲染路径都已改为递归（改动时必须三处同步）：

| 路径 | 文件 | 函数 |
|---|---|---|
| 网页练习 | `src/app/render.js` | `leaf()` |
| HTML 导出 | `py/mathml.py` | `_mi_or_mn()` |
| Word 导出 | `py/make_paper.py` | `_minner()` |

`py/build_html.py` 的 `_rich_html()` 走 `to_mathml()`，自动继承修复。

### 2. 参数尾部要清掉多余逗号

PDF 提取时根号后紧跟的逗号常被误吞进花括号：

```
「底面半径为 √2 的圆锥」  →  \sqrt{2,}
```

不清理就渲染成 √(2,)。三处都用 `_trim_*` 去掉**尾部**孤立逗号；
只去尾部，不动 `\sqrt{2,5}` 中间的逗号（误删会改变语义）。

## 四之二、打包：为什么没有现成的 exe，以及怎么自己打

### 沙箱无法编译，但配置已用真 CLI 校验过

**装不上 Rust**：实测 `static.rust-lang.org`、清华 rustup 镜像、
`crates.io`、Ubuntu apt 源全部返回 403。
所以无法在这里执行 `cargo build`，也就产不出 exe。

**但配置不是靠人工审查的** —— 环境里预装了真正的 Tauri CLI 2.11.4，
用它做了两轮校验：

1. `npx tauri info` —— 直接报错，暴露出一个真实 bug（见下）
2. 用 CLI 自带的 `config.schema.json` 跑 JSON Schema 校验 —— **0 错误**

### 用真 CLI 抓到的三个 bug

**① `devUrl` 不是合法 URI（会直接导致 build 失败）**

```
Error `"tauri.conf.json"` error on `build > devUrl`:
  "../src/index.html" is not a "uri"
```

之前为了"与官方 vanilla 模板一致"把 devUrl 写成文件路径，
但 Tauri 2 要求它必须是 `http://...` 这样的 URI。
本项目是零构建前端、根本没有 dev server，
所以**直接删掉 devUrl**，只留 `frontendDist: "../src"`。

这个错误 `tauri dev` 和 `tauri build` 都会立刻触发，
属于"一跑就崩"级别。

**② resources 路径写错（打包后缺 Python 脚本和题库）**

```json
"resources": ["py/**/*", "data/**/*"]      ← 错
"resources": ["../py/**/*", "../data/**/*"]  ← 对
```

路径相对 `src-tauri/` 目录，而 `py/`、`data/` 在它的上一级。
写错的话编译能过、安装也能装上，
但打开后找不到 `py/main.py`，**所有功能失效且不报错**。
这种"静默失败"比编译错误危险得多。

**③ dev_bridge 参数解析会崩**

```python
PORT = int(sys.argv[1])     # 只认位置参数
```

输入 `--port 8765` 或 `--help` 会抛
`ValueError: invalid literal for int() with base 10: '--port'`，
报错完全看不懂。已改为支持 `8765` / `--port 8765` /
`--port=8765` / `--help` 四种写法。

顺带修了 `SLICES` 路径：切片在 `src/slices/`（前端目录内），
原来指向项目根的 `slices/`，浏览器模式下图片全部 404。

### 一键打包脚本

| 平台 | 文件 | 用法 |
|---|---|---|
| Windows | `一键打包-Windows.bat` | 双击 |
| macOS | `一键打包-mac.command` | 双击 |

## 七、人工审核录入（当前主路径）

### 为什么要切换

自动提取的失真无法靠调参解决，根子在 PDF 本身：

```
原卷 PDF 提取结果：
定义在R 上的奇函数f x 满足f 2 - x = f x ，且在0,1 上单调递减
```

函数括号、区间括号全部丢失。**这些括号在 PDF 里是矢量绘制而非文本字符** ——
无论怎么调正则都提取不出来，只能人工还原。

### 怎么录

题目内容人工（或 AI 读 PDF 原文后）重建为规范 LaTeX，
通过 `py/hand_input.py` 入库。入库时做校验：

```python
from hand_input import add
add({
    'type': '选择',
    'stem_text': '定义在 $\\mathbb{R}$ 上的奇函数 $f(x)$ 满足 $f(2-x)=f(x)$...',
    'opts': [['A','30'], ['B','14'], ['C','12'], ['D','6']],
    'answer': 'A',
    'kp': '函数与导数', 'kp2': '对称性与周期性',
    'review': '原卷作 f(x)=1，据详解判定应为 f(x)=-1，已修正',
})
```

`review` 字段记**改了什么、为什么改** ——
人工录入的全部价值就在这里，不记等于白审。

### 录入的三类修复（以样卷 3 题为例）

| 问题 | 原文 | 修正后 |
|---|---|---|
| 函数括号 | `f x`、`f 2 - x` | `$f(x)$`、`$f(2-x)$` |
| 区间括号 | `0,1`、`-1,11` | `$(0,1)$`、`$(-1,11)$` |
| 分数与下标 | 上下两行、`x1` | `$\frac{1}{4}$`、`$x_1$` |

**还发现并修正了一处原卷笔误**：第 1 题题干作 `f(x)=1`，
但【分析】【详解】全程计算 `f(x)=-1` 得 30，与答案 A 吻合 ——
判定为负号丢失，已修正并记入 `review`。

### 渲染链路的扩展

人工录入用标准 LaTeX，而 `split_rich()` 只认
`\frac / \sqrt / _{} / ^{}` 四种模式（那是为自动提取设计的）。
直接喂进去会**原样输出源码**，屏幕上看到
「定义在 $\mathbb{R}$ 上的奇函数 $f(x)$」。

新增的支持：

1. `split_rich()` 识别 `$...$`，产出 `('L', 源码)` 片段
   - **类型用 `L` 不用 `x`**：`x` 已被 `mergeScript()`
     用作「待合并的上下标」临时类型，复用会让公式被当上下标处理
2. `mathml.latex_inline()` —— 通用 LaTeX → MathML（递归下降解析）
3. `mathml.latex_expand()` —— 宏展开为 Unicode（Word 端用）
4. 三端渲染同步：`build_html` / `make_paper` / `render.js`

支持范围：数集 `\mathbb{R}`、关系符 `\le \ge \ne`、希腊字母、
`\frac \sqrt`、上下标（含 `x_1^2`）、函数名、`\text{}`、
`\left \right`，以及嵌套。

### 第二批录入发现的新问题

录入到 10 题时暴露出三个新坑，都已修复并加固：

**① `\dfrac` / `\tfrac` 未被支持**

```html
<!-- 修复前：落进"未知宏"分支，分数结构整个丢失 -->
<mi>dfrac</mi><mn>9</mn><mn>4</mn>     页面上显示 "dfrac94"
```

`\dfrac` 是 `\frac` 的变体，行内渲染二者完全等价。
早期只认 `frac`，`\dfrac` 走到未知宏分支被输出成标识符。

三处同步修复：

| 层 | 处理 |
|---|---|
| HTML (`mathml.latex_inline`) | `frac/dfrac/tfrac` 三个名字走同一分支 |
| Word (`mathml.latex_expand`) | 先归一成 `\frac` —— OMML 没有 display/text 之分，且 `split_rich` 只认 `\frac` |
| 前端 (`render.js`) | 同 HTML |

**归一必须在"保留结构命令"之前做**，否则 `\dfrac` 会被当成结构命令原样保留，
然后 `split_rich` 匹配 `\frac` 失败，整个分式退化成文本。

**② 长公式选项被 CSS 裁掉**

```css
.opt { white-space:nowrap; overflow:hidden; text-overflow:ellipsis; }
```

选项分列时把 `\frac{...}{...}` 统一替换成 `'xx'` 再算长度，于是

```
$f(2017)<f(2018)<f(2019)$   算成 2 字符 -> 判 4 列
实际渲染宽度 20+ 字符 -> 单元格放不下 -> overflow:hidden 裁掉
```

页面上只剩「A．B．C．D．」看不到内容。这类问题只在 HTML 端出现，
Word 端没有 overflow 概念所以"看起来正常" —— 也正是 user 报的现象。

修法两层：

1. `_math_len()` 按公式**真实内容**长度算，并乘 `FORMULA_WIDTH_FACTOR = 1.5`
   （斜体字母、运算符间距、分式占两行，公式比纯文本更占宽度）
2. 含 `$...$` 的选项加 `.opts-noclip` 类，`overflow:visible`

修复后：短选项 4 列、中等公式 2 列、长公式 1 列。

**③ 教辅里有完全重复的题**

变式 17 与变式 16 **题干、选项、答案全部相同**。
机械提取会把它们当两道不同的题收进来，孩子做专项时连做两遍一模一样的题。

### 答案卷题号全为 0（且顺序与试卷不一致）

**现象**：答案与解析卷里每题都是「0．【答案】」，来源显示「 数学 · 第 0 题」。

**根因**：`cmd_export_answer` **没有调用排序编号函数**。

```
cmd_export_docx   →  auto_sections()  →  重排 num = 1..N   ✓
cmd_export_answer →  （直接传 picked）→  用原始 num        ✗
```

人工录入的题 `num` 默认是 0（`hand_input` 不设此字段），
所以答案卷全部显示 0。

真题卷看起来正常，只是因为它们的 num 恰好已经是 1..N。

**比题号错更严重的是顺序不一致**。试卷按 `sort_key` 排序
（科目出现顺序 → 题型序 → 题号 → id），答案卷用 `_pool()` 的原始顺序。
两者不同，孩子对着答案卷找第 5 题，看到的其实是另一道题的解析。
题号错一眼能看出来，顺序错很难发现。

**修法**：抽出 `order_and_number(sub, qs)`，试卷（`auto_sections` 内部）
与答案卷都调用它，保证同源。

```python
# make_paper.py
def order_and_number(sub, qs):
    ...                      # 算科目顺序 → 排序 → 编号 1..N
    return ordered

def auto_sections(sub, qs):
    ordered = order_and_number(sub, qs)   # ← 复用
    ...

# main.py cmd_export_answer
ordered = MP.order_and_number(sub, picked)   # ← 新增
path = MP.build_answer(ordered, ...)
```

**顺带修的：来源字段**

```python
src = '%s %s' % (picked[0].get('year', ''), sub)   # 旧：用第一题的年份
```

人工录入的题没有 `year`，所有题的来源都显示「 数学」。
改成优先用每题自己的 `src` 字段：

```python
src_txt = (q.get('src') or '').strip() or src_label
```

现在正确显示「2024高中数学热点题型归纳 · 对称性与周期性 变式16 · 第 9 题」。

**验证方式**：不能只比对题号序列（两份都是 1..10，看不出顺序是否一致），
必须**对照题干与解析的语义**：

```
第 1 题  定义在R上的奇函数f(x)满足f(2-x)   由f(2-x)=f(x)知图象关于直线x=1
第 4 题  （2008湖北）f(x+4)=f(x)          由f(x+4)=f(x)知周期为4，把f(7)…
第 10题  偶函数，f(1/2+x)=f(3/2-x)         由对称性得f(x)=f(2-x)，结合偶函数…
```

语义全部吻合才算对上。

已加 5 条回归用例（乱序输入 → 重排为 1..N、同型保序、
试卷与答案卷编号一致、来源用每题自己的 src、题号不再为 0）。

### 本次修的两个 bug

**① 选项跨行：分母及后续内容被并进题干**

教辅选项常含分数，PDF 里分子分母是上下两行：

```
A. (0, 2) ∪ (9
             2        <- 分母在下一行

```

早期按行扫描，遇到 `A. xxx` 就把**那一行**当整个选项。

修法：**选项内容跨行累积**，边界是"下一个字母标记"或"【答案】"：

```python
marks = [(m.start(), m.end(), m.group(1)) for m in OPT.finditer(head)]
marks = [x for x in marks if x[0] == 0 or head[x[0]-1] == '\n']
for i, (a, b, L) in enumerate(marks):
    e = marks[i+1][0] if i+1 < len(marks) else len(head)
    opts.append((L, clean(head[b:e])))
```

| 含空选项 | 有 | **0** |

#### 切题：必须用【答案】做锚点校验证

这是整个提取中最关键的一步，踩了三层坑：

**坑 1：详解里的分类编号被当成题号。**
教辅详解常用「1、若 A 中的最大数为 1 时…」分情况讨论。
题号正则若把顿号 `、` 也算分隔符，就会把详解切成假题目。
去掉 `、` 后，假题目从 435 降到一批。

**坑 2：小数点被当成题号。**
详解里「10.9 > 1.10 = 1，所以 c > a > b」，
其中 `10.` 会被 `\d+\.` 匹配成题号 10，
后半句「9 > 1.10 = 1…」就成了新题干。
改正则为 `[.．](?=\s)` —— 要求点号后必须是空白。

**坑 3（最隐蔽）：详解被切成多道假题。**
即使前两条都改了，仍有 28% 的题目题干尾部是
「∴元素个数有 5 个. 故选：D．」这种详解结尾。
根因是详解内部还有用点号编号的分情况条目，
它们后面到下一个题号之间**没有【答案】**。

最终方案：**用【答案】反向校验证题号**。

```python
while True:
    for i, (a, b, n) in enumerate(idx):
        end = idx[i+1][0] if i+1 < len(idx) else len(block)
        if not ANS.search(block, a, end):
            idx.pop(i); break     # 这段没有答案 -> 是详解碎片
    else:
        break
```

反复剔除直到稳定。效果：

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 题目数 | 1955 | **1395** |
| 带答案 | 72% | **100%** |
| 带详解 | 68% | **95%** |

少了 560 道题，但**每一道都是完整的真题目**。
宁缺毋滥 —— 没答案的题对练习毫无价值，
混在库里还会让「按题型刷」变成刷详解片段。

## 六之九、批次（Batch）：整批筛选与删除

### 需求

> 之前的所有题目都打上标记。后续补充其他题目后，
> 可以筛选出这些题目并全部删除。

### 数据模型

```
题目 q['batch'] = 批次ID
批次表 batches.json = { 批次ID: {名称, 时间, 来源, ...} }
```

**题数不落盘**，每次从题库实时统计。

|---|---|---|---|
| `导入-初始216题` | 2021–2026 真题（初始导入） | 216 | 数学 123 / 物理 93 |

### 新导入自动归批

`_commit()` 每次导入生成新批次 `导入-年月日-时分秒`。
**不复用旧批次** —— 混入后就再也分不开了。

### 打标命令

```bash
batch-tag                      # 只标「未标记」的（默认，安全）
batch-tag --all                # 强制重新标记全部（覆盖已有批次）
batch-tag --ids M-2021-001,... # 只标指定题目
```

默认是「只标未标记的」：**防止重复打标覆盖已有批次**。
想重来时用 `--all`。

### 删除的保护

`batch-delete` 是高危操作，四重保护：

1. `--batch` 必填，空值直接拒绝（防误删全部）
2. 确认弹窗，提示先备份
3. 先备份 `bank.json`
4. **连带清理 `progress.json` 里对应的练习记录** ——
   否则 progress 越攒越多，复习页混着已删题目

**切片图片不删**：图片按题目ID命名但可能跨批次复用，
误删会破坏其他批次。磁盘占用可接受。

### 写入加了锁

```python
_WRITE_LOCK = threading.Lock()
```

单命令串行时不需要，但 `dev_bridge` 是多线程 HTTP 服务 ——
两个请求同时触发写库（如「导入PDF」与「标记题型」并发），
会各自写 .tmp 再 replace，互相覆盖甚至产生截断文件。

实测复现过：selftest 里出现 `Expecting value: line N` 的
JSON 解析失败，根因就是并发写。加锁后消失。

题库页新增两块：

- **批次管理卡片**：列出所有批次（名称、时间、来源、题数、科目分布），

## 六之八、复习参数：移到「设置」页签

### 原来在哪

硬编码在 `py/main.py` 顶部：

```python
LADDER = {-2: 1, -1: 2, 0: 0, 1: 7, 2: 15, 3: 30, 4: 60, 5: 120}
```

改一次要动代码、重新打包。现在统一存 `data/config.json`，
设置页改完**保存即生效**。

### 可调参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `ladder[-2]` | 1 | 连错 2 次以上，几天后重现 |
| `ladder[-1]` | 2 | 错 1 次，几天后重现 |
| `ladder[1..5]` | 7/15/30/60/120 | 做对 1~5 次后的间隔 |
| `mix_new_pct` | 70 | 组卷时新题占比 |
| `mix_wrong_pct` | 30 | 组卷时错题占比（两者和为 100） |
| `daily_new_cap` | 20 | 每日新题上限 |
| `done_level` | 3 | 达到此等级视为已掌握 |
| `due_soon_days` | 3 | 到期提前提醒天数 |

设置页对每条都写了 rationale，比如 -1 档为什么是 2 天而不是 7 天。

### 校验：非法值不落盘

```python
merged = dict(DEFAULT_CONFIG)      # 先与默认合并
for k in DEFAULT_CONFIG:
    if k in cfg: merged[k] = cfg[k]
cfg = merged                       # 再校验
```

**先合并再校验**是必须的：前端只传改动的那几项时，
其余字段取 0 会冒出一堆假报错（「配比之和必须是 100，当前 0」）。

校验规则：
- 配比之和必须为 100
- `ladder[-1]` 必须 > 0 —— 否则错题永远 0 天后到期，等于不复习
- 间隔不能为负

不通过就 return，`save_config` 根本不执行（半截配置比旧配置更危险）。

向后兼容：旧版 config.json 缺字段时，`load_config` 用默认值补齐。

### 组卷配比真的生效

新增 `_pick_mixed()`：按配比分别从「新题池」和「错题池」抽样。

两个细节：
- **任一类不足时由另一类补足**，保证凑够题数（否则错题少时组出半张卷）
- **每日新题上限只卡新题**，且砍掉后由错题补回 ——
  否则孩子错题多的时候，会被上限卡住练不了错题

### 原子写加了 fsync

```python
def _atomic_write(path, data):
    with open(tmp, 'w', encoding='utf-8') as f:
        json.dump(data, f, ...)
        f.flush()
        os.fsync(f.fileno())      # ← 不能省
    os.replace(tmp, path)
```

`save_config` / `save_progress` / `_save_bank` 三处统一走它。

**一个排查了很久的坑**：本环境（overlayfs）下，
`os.replace` 之后紧接着的 `open()` **可能返回旧内容**，
规律是「两次写入之间若夹着一次读，第二次读到的仍是第一次的值」：

```
写 A -> 读(得A) -> 写 B -> 读(仍得A)     ← 复现
写 A -> 写 B   -> 读(得B)                ← 正常
```

这不是应用 bug：fsync 已加，且真实使用中前端**直接用 save 的返回值**，
不依赖重读。但写测试时会被坑，所以「配置驱动行为」的断言
一律用 monkeypatch 隔离文件 IO。

- `tools/check_config_io.py` —— 文件落盘往返，**单独跑，0 失败**
- `tools/selftest.py` 第 23 组 —— 默认值 / 向后兼容 / 非法拒绝不落盘 /
  部分更新 / 配置驱动复习日期 / 配比生效 / 新题上限

## 六之七、三层职责边界 + 双向挂ID 契约

用户提的这条点破了原实现的模糊地带：

> 题型的全局ID是给题目引用的，题目的全局ID是给题型引用的，
> 题目和题型**互相挂ID**，多对多。
> 大知识点和小知识点**只需要作为目录**。

### 三层职责

| 层级 | 是什么 | 有 ID | 参与索引 |
|---|---|---|---|
| 一级 大知识点 | **纯目录** | 否 | 否 |
| 二级 小知识点 | **纯目录** | 否 | 否 |
| 三级 题型 | **实体节点** | 是 | **是** |

大/小知识点只负责组织题型、提供筛选维度，**本身不需要 ID** ——
它们不会被挂到题目上，也不会被题目引用。
索引只发生在**题型 ↔ 题目**之间。

代码层面已断言：不存在 `level1_id` / `level2_id` 这类分配函数，
`level1()` / `level2()` 返回的都是纯字符串列表。

### 互相挂 ID（多对多）

```
题目 M-2021-018  .topics    = ["M-T-135", "M-T-156"]     ← 挂题型ID
题型 M-T-135     .questions = ["M-2021-018", "M-2025-011"]  ← 挂题目ID
```

两个方向都是多对多：
- 一题挂多题型（一道导数压轴题同时是「利用第一问」和「极值点偏移」）
- 一题型挂多题（「错位相减」下有历年多道真题）

### 存储仍只存单向

关系的**语义**是双向的，但**持久化只存题目→题型**：

```
bank.json   q['topics'] = [题型ID...]        ← 唯一权威
运行时      nd['questions'] = [题目ID...]     ← 反建
```

双写必然不一致。反索引每次加载时 `rebuild_qindex()` 重建。

### 契约校验：verify_index()

双向挂ID 是个**契约**，要有办法验证它没被破坏：

```python
ok, problems = verify_index(bank)             # 默认不重建
ok, problems = verify_index(bank, rebuild=True)  # 先重建再校验
```

**默认 `rebuild=False` 是关键**。第一版写成默认重建，
结果「幽灵引用」（题型里挂着已删的题目ID）永远查不出来 ——
因为 rebuild 会用题目的 topics 整体覆盖 questions，幽灵当场被洗掉。

破坏情形与检出：

| 破坏 | 检出 |
|---|---|
| 题型引用了不存在的题目（幽灵） | `verify_index()` 默认模式 |
| 题目挂了不存在的题型ID | 两种模式都检出 |
| 反索引缺失 | 两种模式都检出 |

这个错误**不会抛异常**，只表现为「按题型筛出来的题对不上」，
所以必须主动校验。

### 回归用例

`tools/selftest.py` 第 22 组：
L1/L2 是纯字符串、不存在 ID 分配函数、只有题型是实体、
一题挂多题型、一题型挂多题、双向对称（两个方向都遍历断言）、
幽灵只有在不重建时才检出、坏题型ID 可检出。

## 六之六、题型节点：从「字符串」升级为「实体」

### 用户提的关键改进

> 将题型作为标签挂在题目上，一个题目可挂多个题型；
> 同时把题目ID挂在题型下方，双向索引。

原实现里，题型只是小知识点下的一个**字符串**，
「综合与交叉」是个容器 —— 题型和知识点还是混在一个维度里。

现在的模型：

```
大知识点(一级) ──┐
小知识点(二级) ──┴── 题型(三级，是**节点**) ←──→ 题目
                        ↑                          ↑
                   有全局ID                    可挂多个题型
                   可属多个父                  反查得到题型
```

题型和知识点是**两个独立维度**：知识点回答"考什么"，题型回答"怎么考"。

### 数据结构

```python
TOPICS = {                      # 全局题型节点表
  "M-T-135": {
      "id": "M-T-135",
      "name": "数列与导数",
      "subject": "数学",
      "primary": ("函数与导数", "导数压轴小题(一)"),   # 主归属，唯一
      "cross": ["数列"],                            # 交叉归属，多父
      "questions": ["M-2021-018", ...],             # 挂的题目ID
  },
}
```

ID 规则 `{科目码}-T-{三位序号}`，按遍历顺序分配 —— **只要目录不变，ID 就稳定**。
这点很关键，因为 ID 会被存进题目里。

**复合题型只占一个节点**：挂多处时不复制，只是在 `cross` 里多记一条。
所以「数列与导数」从「函数与导数」和「数列」两个入口取到的是**同一个节点**。

### 双向索引：只存单向

```
题目 → 题型   存在 bank.json 的 q['topics']（唯一权威）
题型 → 题目   运行时 rebuild_qindex() 从题库反建
```

**为什么只存单向**：双写必然不一致。题目上的标签是权威，
反索引每次加载时重建，216 题的 O(n) 扫描代价可忽略。

### 自动标注不可行（实测）

尝试用关键词把 422 个题型自动挂到 216 道题上：

| 匹配强度 | 命中 |
|---|---|
| 全特征词匹配 | **0 / 216** |
| 单特征词匹配 | **1 / 216** |

原因：教辅题型名（「长方体模板1：三线垂直型」「错位相消法三种思维求法」）
与真题题干（「在三棱锥 A−BCD 中，平面 ABD ⊥ 平面 BCD」）**语言几乎不重叠**，
且真题题干还有公式占位损耗。

**结论：题型标签必须人工标注。**这是整套系统里唯一无法自动化的环节，
也恰恰是它有价值的原因 —— 如果机器能判，说明这个标签信息量不大。

### 标注工作流

1. Excel「题型总表」sheet 查题型 ID（422 行，含主归属/交叉/已挂题数）
2. 在「题库索引」第 30 列「题型标签(TopicID)」填，多个用分号隔开

## 六之五、复合题型：多父归属

### 为什么必须支持

一个题型**只能挂一处**会直接造成漏题：

```
「立体几何中的轨迹」  主挂在 解析几何/轨迹方程
   ↓
按「立体几何」筛 → 筛不到它
```

而高考压轴题几乎都是跨块综合 —— 圆锥曲线压轴考向量、导数压轴考数列、
解三角形考四心向量。这类题恰恰是最容易丢分的，漏掉代价最大。

### 结构

每个一级下有一个名为「**综合与交叉**」的小知识点，
作为**交叉归属的挂载点**：

```python
TOPIC_XREF = {
    "数学": {
        "集合与排列组合概率": ["概率统计", "计数原理"],
        "立体几何中的轨迹":   ["立体几何"],
        "数列与导数":         ["数列"],
        ...
    },
}
```

- `level3(subj, l1, l2)` 默认**并入**交叉过来的题型
- `level3(..., include_cross=False)` 只取原生，用于**统计**（避免重复计数）
- `topic_owners(subj, topic)` 反查：返回全部归属，主归属排第一
- `is_cross(subj, topic, l1)` 判断在此一级下是否为交叉

### 交叉关系的自动生成

从题型名里识别**另一块的标志性专有名词**（不能用「函数」这类泛词）：

```
目标一级      触发词
三角函数      三角函数 / 正弦 / 余弦 / 解三角形 / Asin / ωx
数列          数列
平面向量      向量
解析几何      圆锥曲线 / 椭圆 / 双曲线 / 抛物线
不等式        柯西 / 均值 / 绝对值 / 不等式
...
```

两条**降噪规则**（不加的话会多出近一倍噪音）：

1. 目标一级 == 当前一级 → 不算交叉
2. 主归属的 (一级名 / 二级名) 里已含该触发词 → 不算交叉
   （如「导数不等式证明」下的「证明不等式N」，本就是不等式内容）

收紧前后：**63 → 35 个题型**，质量干净。

### 误判代价不对称

宁可漏标交叉，也不要乱标：

- 漏标 → 按某块筛时少一题，**多刷一遍就能补上**
- 误标 → 不相关的题混进专题卷，**浪费孩子的时间**

所以触发词只收**专有名词**，「函数」「导数」这类高频泛词基本不用。

### 前端呈现

题型清单里，交叉归属的题型带绿色小尾巴：

```
数列与导数  ↔数列
```

悬停显示「同时属于：函数与导数、数列」。
这样按「数列」刷到它时，孩子知道这块还连着导数。

### 数据规模

| | 数量 |
|---|---|
| 原生题型 | 422 |
| 含交叉引用 | **460**（+38 条交叉关系） |
| 复合题型 | 35 个 |

### 回归用例

`tools/selftest.py` 第 20 组：6 个典型复合题型的归属断言、
主归属唯一且排第一、每个一级都有挂载点、

## 六之三之负四、选项标记：分隔符必须强制

### 症状

导出卷子第 9 题：

```
A．A 比
B．先落入篮筐
C．A 在最高点的速度比 B 在最高点的速度小
D．A、B 上升到某一相同高度时的速度方向相同
```

A 被截断，**真选项 B 整条消失**。

### 根因

选项标记的正则把分隔符设成了可选：

```python
OPTSCAN = re.compile(r'(?:^|[\s　])[（(]?([A-D])[）)]?\s*[．.、]?\s*')
#                                                        ↑ 可选，这是祸根
```

原句 `A．A 比 B 先落入篮筐` 里，正文的 **B** 也被当成选项标记：

```
A．→ 选项 A     " B " → 选项 B
   A = "A 比"
   B = "先落入篮筐"      ← 真的 B 行被跳过，因为已凑够 4 项
```

统计：**12 份真题共 178 行**受影响。典型误伤：

| 原句 | 误判 |
|---|---|
| `A．A 比 B 先落入篮筐` | A="A 比"、B="先落入篮筐" |
| `设集合 A = {...}, B = {...}` | 拆出 4 个假选项 |
| `三棱锥 A − BCD` | A、B、C、D 全成选项 |
| `(A) OP₁ = OP₂ (B) AP₁ = AP₂` | 多出 1 个假 A（来自 `A_{1}`） |

### 修法：分隔符或括号对，二选一且必须出现

```python
OPTSCAN = re.compile(r'(?:^|[\s　])(?:\(([A-D])\)|（([A-D])）|([A-D])\s*[．.、])\s*')
```

三种合法形态，三个捕获组，`_opt_letter()` 取非空的那一个。

### 配套：图片选项行要单独识别

有些题的选项**就是图**（肥皂膜侧视形状、光电效应图像），
原卷只有一行孤零零的 `A B C D`，一个分隔符都没有。
强制分隔符后这类会全部漏掉，所以补一条独立规则：

```python
IMG_OPT_LINE = re.compile(r'^[A-D](?:[\s　]+[A-D])+$')
```

判据是 **fullmatch + 至少两个字母** —— 几何题正文不会恰好只剩几个
孤立大写字母，所以不会误伤（已验证：几何顶点 A/B/C/D 不会被误判）。

### 修复效果（重拆 12 份真题）

| | 旧 | 新 |
|---|---|---|
| 带选项的题 | 149 | **143** |
| 过短选项（<3字） | 69 | **64** |
| 丢失的 6 项 | — | 全部确认为**假选项** |

那 6 题的旧"选项"长这样，全是几何顶点或集合名，本就不该有：

```
M-2021-018  A="类问题的概率为 0.8, 能正确回答"   ← 原文"有 A, B 两类问题"
M-2021-019  A="C 上,"                          ← 原文"△ABC 的内角 A, B, C"
P-2022-014  A="点由静止开始做匀加速直线运动"      ← 原文"从 A 点…到达 B 点"
```

### 回归用例

`tools/selftest.py` 第 19 组：锁死「正文裸字母不算标记」
「集合名不算选项」「4 个正常选项仍能识别」「括号式仍能识别」
「图片选项行仍匹配」，并用真实题库断言 P-2021-009 的四个选项。

## 六之三之负三、上下标：从源信息判定，不是事后猜

### 症状

`x3` 到底是 x³（立方）还是 x₃（下标）？`a2` 是 a² 还是 a₂？
事后的正则猜测**必然有错** —— 两者在文本层面完全一样。

### 正解：拆解时就用源信息

PDF 里上下标是**无损信息**，只是被提取流程压平了：

| 来源 | 源信息 | 可靠性 |
|---|---|---|
| LaTeX 生成的 PDF | **字体名带设计尺寸**：`CMMI10`(正文) / `CMMI7`(下标) | 极高 |
| Word 生成的 PDF | 字号 + 基线偏移（`origin[1]`） | 高 |
| DOCX | `run.font.superscript` 布尔属性 | 极高（待接入） |

实测 2021 数学卷（LaTeX 生成）：

```
'17.'   sz=10.5  oy=505.1  font=LMRoman10-Regular   ← 正文
'a'     sz=10.5  oy=505.1  font=CMMI10              ← 正文
'n'     sz= 7.0  oy=506.7  font=CMMI7               ← 下标（字体名直接标注）
```

### 判据：字号比例 + 偏移方向

```python
SCRIPT_SIZE_R = 0.85   # 字号 < 正文 × 0.85 → 是上下标
SCRIPT_MAX_DY_R = 0.7  # |偏移| < 正文 × 0.7（相对值，字体无关）
```

**为什么不能设绝对偏移阈值** —— 实测铁证，核素符号 ¹⁴₇N：

```
'14' (上标) dy = -3.6pt
'7'  (下标) dy = +0.4pt   ← 上标占了上方空间，下标被压到近乎贴基线
```

而数学卷 a₁ 的下标偏移是 +1.6pt。**同一个「下标」差 4 倍**，
任何绝对 pt 阈值都必然在某一卷失效。用相对字号则稳定（0.04 vs 0.15 都能覆盖）。

**判据只用偏移的符号定方向，不用大小筛选。**

### 三个必须踩过的坑

**1. 基底搜索必须 y、x 双重约束**

只比对 x 不比对 y 会跨行误配。核素 `14`(x=378.2) 与**页面顶部**另一个
span 的 x 范围重叠，被当成基底，dy 算出 +14.4（跨了 8 行），
上标被判成下标。

真实上下标 |dy| ≤ 0.4×字号，跨行假关系 ≈ 1.4×字号（一个行距）——
用 |dy| 上限即可天然区分。

**2. 连续上下标要链式归属**

`a_{n+1}` 被 PDF 拆成 `a` | `n` | `+1` 三个 span。
`+1` 与基底 `a` 之间隔着 `n`，x 距离超容差 → 找不到基底。
解法：与**同基线、x 紧邻的已标记 script** 继承类型和基底。

**3. 基底只定一次，别搜两遍**

曾在 span 阶段搜一次基底、到 item 阶段又搜一遍，
两遍的候选集和容差不一致 → `a_{n+1}` 的 `+1` 在第二次搜索中
失败被静默丢弃。现在基底存 span 对象引用（`_base`），只搜一次。

**4. 合并必须在分式识别之后**

分式 `rac{∆Q}{t} = rac{10^{-9}}{2×10^3}` 的上标 `−9`
与前一个分式的分母 `t` x 邻接，提前合并会误配成 `t^{−9}`。
现在 `_apply_script_merge` 跳过已标记 `_used` 的 span，
**分式内部保持平文本** —— 保守但不误配。

### 保守原则

找不到可靠基底的（如核素 `147N`）**不标记**，保持平文本。
宁可不转换，也不能把上标判成下标 —— 后者会让孩子算错题。

### 渲染：四端都要支持

存 LaTeX `_{}` / `^{}`，四端渲染：

| 端 | 下标 | 上标 | 同时有 |
|---|---|---|---|
| 网页 | `<msub>` | `<msup>` | `<msubsup>` |
| HTML 导出 | `<msub>` | `<msup>` | `<msubsup>` |
| Word | `<m:sSub>` | `<m:sSup>` | `<m:sSubSup>` |

**命名陷阱**：根号段标记是 `('s', ...)`，上/下标组若也叫 `'s'`
会让 `2\sqrt{3}` 的根号被当成下标组，与前面的 `2` 合成 `msub`。
上/下标组改用 `'x'`。已固化进测试。

### 效果（重拆 12 份真题）

| | 旧（正则猜） | 新（源信息） |
|---|---|---|
| 下标 | 41 题 | **62 题** |
| 上标 | 0 题 | **55 题** |

## 六之三之负二、下标还原（核心难点：歧义）

### 症状

卷面上是平文本 `an+1`、`F1`、`A1B1C1`，而原卷是 aₙ₊₁、F₁、A₁B₁C₁。

### 根因

PDF 提取把下标的**字号+基线偏移**丢了，压成了普通字符。
而「字母+数字」**天然歧义**：`x3` 可能是 x³（立方）也可能是 x₃（下标），
所以**不能无脑转换**，必须靠上下文判定。

### 三条规则（置信度从高到低）

| 规则 | 模式 | 例 | 依据 |
|---|---|---|---|
| 1 | 大写字母 + 数字 | `F1` `P2` `A1B1C1` | 几乎必是下标 |
| 2 | 字母 + n（可带 ±数字）、字母 + 数字n | `an` `an+1` `a2n` `Sn` | 数列项 |
| 3 | 小写字母 + 数字 | `x1` `x2` | **仅当同题干有「该字母+n」** |

规则 3 的证据逻辑：`x1, x2, …, xn` 里同时存在 `xn`，
说明这是下标序列；没有这个证据的一律不动 ——
`x3 = x³`、`y2 = y²`、`b2 = b²` 都是上标，改了就错。

### 两个必须放宽的前置断言

```python
_PRE     = r'(?<![A-Za-z0-9\_])'   # 规则 1、2
_PRE_NUM = r'(?<![a-z\_])'          # 规则 1 专用
```

- 规则 1 要放行**数字**：否则 `A1B1C1` 只有 A1 被转（B1 前是数字 1）
- 规则 1 要放行**大写**：否则 `AB = AA1` 漏掉（侧棱 AA₁，第二个 A 前是大写 A）

### 一个必须排除的函数名

`ln`（自然对数）。规则 2 会把它当成 `l` 下标 `n`
—— 因为 `l` 前面通常是空格，能通过前置断言。
`sin`/`cos`/`tan` 则天然安全（n 前面是字母，被前置断言挡掉）。
黑名单已含 `ln sin cos tan log min max sec csc`。

### 渲染

存 LaTeX `_{}`，三端渲染都要支持 `<msub>` / `<m:sSub>`：

| 端 | 文件 | 关键点 |
|---|---|---|
| 网页/HTML | `src/app/render.js`、`py/build_html.py` | **必须过 `merge_sub()`** |
| Word | `py/make_paper.py` | `omml_sub()` |

`split_rich` 产出扁平序列，`a_{n+1}` 被切成文本「a」+ 下标「n+1」两段；
不合并的话下标段单独渲染会**丢掉基底**。
`build_html._rich_html` 曾漏掉 `merge_sub`，导致 HTML 端下标完全不出 ——
这条已固化进测试。

## 六之三之负一、作答位：去重，不是删除

### 症状

上一版把题干尾部的 `（ ）` 全删了，卷面变成
「…单调递增的区间是 A．… B．…」——**反而不像试卷**。

### 根因：判断错了

我以为「选项已排到题干下方，作答位就多余」。
**事实相反**：高考卷选择题题干末尾本来就有「（　　）」，
它和下方选项是共存的，学生做题时习惯看到它。

### 规则

```python
ANSWER_BLANK = '（　　）'      # 全角括号 + 全角空格
TAIL_BLANK   = r'\s*(?<![A-Za-z0-9])(?:[（(]\s*[)）]\s*)+$'
```

先清掉尾部**全部**空括号 → 再拼**一个**标准作答位。
所以 `（ ）（ ）（ ）（ ）（ ）` 会归一成单个 `（　　）`。

**按题型开关**：

| 题型 | 保留作答位 | 理由 |
|---|---|---|
| 单选 / 多选 | ✅ | 试卷规范 |
| 填空 | ❌ | 填空处渲染成下划线 |
| 解答 | ❌ | 不需要 |

- 句末句号先剥掉，避免「…则。（　　）」
- 幂等：重复调用不会累加

### 依然保留的防护

- 只动**尾部**连续空括号；中间的是公式占位符，删了会丢内容
- 括号前不得是字母/数字，避免误伤 `f( )`、`g( )`
- 非选择题一律不加

## 六之三之零、题干尾部作答位与泄漏选项

### 症状

题干末尾出现 `（ ）` 或连续重复的 `( ) ( ) ( ) ( ) ( )`。

### 根因

**不是提取错误，是原卷自带的作答位。** 原卷选择题在题干末尾
留「（　　）」给考生填答案，组卷网等题库站也是这么存的：

```
2. 设为等差数列，且，则（　　）A．16B．18C．20D．22
```

但我们的渲染把**选项排到题干下方**，这个作答位就成了多余尾巴。
提取时若遇到分栏/换行，还会被重复抓取成 `( ) ( ) ( ) ( ) ( )`。

### 规则

```python
TAIL_BLANK = re.compile(r'\s*(?<![A-Za-z0-9])(?:[（(]\s*[)）]\s*)+$')
```

- 只清**尾部**连续空括号，中间的保留（中间的是公式占位符，
  真实内容常被提取到紧随其后的位置，删了反而丢信息）
- 括号前不得是字母/数字 —— 否则会误伤 `f( )`、`g( )` 这类
  真实函数记号。中文（「为（ ）」「是（ ）」）不受影响，
  因为原卷中文里括号前通常**没有空格**，不能要求空白

### 顺带修的：选项漏进题干

原卷分栏/换行会让 `A．B．C．D．` 被拼进题干：

```
…若二面角 C − AB − D 为 60◦，则（ ） C. 当 AB ⊥ CD 时… D. 当 AB ⊥ 平面 ACD 时…
```

`split_leaked_opts()` 把作答位之后的选项切回 `opts`。
**只补缺失的字母**，不覆盖已有选项 —— 少数题目的 `opts` 提取成了
碎片（如 A="和钉子"），那种必须重新拆卷，不能靠猜，
静默覆盖会把好数据改坏。

### 落地

清洗接在 `_prep_fields()` 里，**入库和渲染各调一次**，
新导入的卷子自动干净；已有数据做了一次性迁移
（bank.json 113 题 + Excel 64 处）。幂等，重复调用无副作用。

### 填空下划线用 border-bottom，不用 text-decoration

`text-decoration:underline` 画在**纯空白字符**上时，部分浏览器
（尤其打印预览）会跳过空白区域，下划线就看不见了。
改用 `display:inline-block; min-width:4em; border-bottom:1px solid`，
任何环境都稳定。宽度由 `T.FILL.blank.width_em` 配置。

### 填空标记必须同时认半角 `.` 和全角 `．`

PDF 提取会把原卷的全角「．」变成 ASCII 句点。
21 道填空题里 **14 道是半角、只有 3 道是全角**；
只写 `．` 的话三分之二的填空处渲染不出下划线。

每条 pattern 都限定「待填位置」（紧跟 `=`/`为`/`是`，或句末、
后接分句标点与括注），所以小数点 `3.14159`、省略号 `· · ·`
都不会被误替换 —— 这四条已固化进测试。

## 六之三之一、分节与编号的单一排序源

### 症状

混编卷出现「填空题分节里躺着物理解答题」「三个选择题大分组」。
根因是**排了两次序，两次顺序不一致**：

| 位置 | 排序键 |
|---|---|
| `auto_sections` | `(题型, 题号)` |
| `_renumber` | `(题号)` |

两者结果不同，而分节再按「各分节题数」依次切分，
题目就被分进了错误的分节。

### 修法

排序键收敛到 `make_paper.sort_key(q)` 一处：

```python
(科目出现顺序, 题型序, 题号, id)
```

`auto_sections` **一次性完成分节 + 编号（1..N）**；
`_renumber` 降级为纯校验（题号不重复、无题遗漏），不再重排。

### 分组键：(科目, 题型)

- 混编卷里数学、物理各成一段，两科都看得见。
  否则整卷只显示首题科目的分节标题，另一科被淹没。
- 标题加【科目】前缀；单科卷不加。

### 多选不靠猜

曾按「前 8 题单选、其余多选」硬切。题目**自带 `subtype`**
（`单选题` / `多选题`），直接读即可 —— 猜会在题量不足 8 时
造出空分节，多选在前时又把单选判成多选。

分节序号在该科内**顺序递增**（一、二、三…），
没有多选题时不会跳号。

## 六之三之二、导出试卷三原则

### 1. `_prep_fields` 绝不能破坏已有数据

曾无条件执行 `' '.join(q.get('stem') or [])`。而入库后的题目
**只有 `stem_text`、没有 `stem` 原始列表**，于是每次调用都把
`stem_text` 覆盖成空 —— 导出的试卷只剩题号和选项，**题干整段消失**，
且没有任何报错。

正确做法：`stem` 存在（刚拆题、在内存里）才重建，否则原样保留。

### 2. 题号必须重排为 1..N

组卷出来的卷子题号要连续。跨年份/跨科目选题时原题号是 3、9、17 这种，
**两科还都有「第 4 题」**。重排必须按**对象身份**排序，
绝不能用 num 反查（会重复取同一题、漏掉另一科的同号题）。

分节顺序也要重排：先按题型（选择→填空→实验/计算→解答），
再按题号。只按题号排会得到「选择→解答→填空→解答」，
同型题还会被拆成多个分节，冒出两个「四、解答题」。

### 3. 题型从题目自身读，不按题号区间推

`T.qtype_of(subject, num)` 查的是**全局规则表，key 只有科目**。
混编卷里物理第 12 题会被套进数学结构（数学 12 题是填空），
判成解答题 → 凭空多出一大片留白。

改用 `_qtype_of_q(q)`：优先读题目自带的 `type` 字段（拆题时已校验），
读不到才回退到内容推测。

### 4. HTML 图片必须显式限尺寸

Word 端有 `_fig_size()` 按 `cm = 像素 / dpi × 2.54` 换算并限高，
HTML 端原先只写了 `max-width:100%` —— 图会按**原始像素**撑开，
710px 宽的图在 A4 上几乎占满一行，高 708px 的图吃掉半张纸。

现在两端同规则：单图上限 10cm、限高 8cm，多图按张数收窄。

### 5. 题干里可能混入分节标题

拆题时若分节标题与题目落在同一文本块（多见于原卷分页处），
会变成「…母线长 三、填空题 为 ( )」。`_prep_fields` 里已加清理。

共 210 条别名。还有 `SPLIT` 处理「光学与近代物理」这类横跨两个

### 展示规则

组卷页展示的是**完整标准目录**，不只是已入库的那些：
已入库的排在前面并标出题数，暂缺的排在后面灰显。
这样即便某科还没录题，也能先把知识点选好。

## 七之一、编译前必读（零构建前端特有的坑）

本项目前端**没有打包器**（不用 Vite/webpack），这带来几个必须绕开的坑。
以下每一条都会导致「能编译但应用不可用」或「打包直接失败」。

### 1. 不能 import 裸模块

```js
await import('@tauri-apps/api/core')   // ✗ 会抛 Failed to resolve module specifier
```

浏览器原生 ES Module 无法解析 `@tauri-apps/...` 这类裸模块说明符。
**必须用 Tauri 注入的全局 API**：

```js
window.__TAURI_INTERNALS__.invoke(cmd, args)                    // ✓
window.__TAURI_INTERNALS__.invoke('plugin:dialog|open', {options}) // ✓
```

`src/app/api.js` 里的 npm 包 import 仅作兜底（将来若接入打包器），
正常路径完全不依赖 node_modules。

### 2. 切片目录必须在 frontendDist 之内

`frontendDist = "../src"`，前端的 `<img src="slices/...">` 相对它解析，
所以切片必须放在 `src/slices/`，**不能放项目根的 `slices/`**。

### 3. 路径不能带前导斜杠

`slices/` 而不是 `/slices/`。带前导斜杠时，`file://` 协议下会解析到
文件系统根目录（不是项目目录），图片全部 404。不带斜杠则
`file://` / `tauri://` / `http://` 三种协议都能正确解析。

### 4. 没设 devUrl 时必须启用 custom-protocol

`Cargo.toml` 里的 `[features] custom-protocol` 不能删。
否则生产构建（`tauri build`）加载不到前端资源，打开就是白屏。

### 5. macOS 的资源布局不一样

| 平台 | exe 位置 | resources 位置 |
|---|---|---|
| Windows / Linux | 安装根 | 与 exe 同级 |
| **macOS** | `xxx.app/Contents/MacOS/` | **`xxx.app/Contents/Resources/`** |

`script_path()` 和 `python_candidates()` 都必须尝试 `../Resources/`，
否则 macOS 上打包后找不到 `py/main.py`。

### 6. 图标必须是真格式

`icon.icns` 不能是改了扩展名的 PNG，macOS 打包会失败。
必须按 `icns` 容器格式（魔数 `icns` + `[type,len,payload]` 块）生成。

## 七之二、几个必须守住的设计陷阱

下面每一条都是实际踩过的坑，改动代码时请务必避开。

### 1. 拆题必须写回题库

`cmd_extract` 若只返回题目而不写 `data/bank.json`，
界面会显示「拆题成功：16 题」，但组卷页一题都找不到 —— 流程完全断裂。

入库时还要做三件事：**先备份 `bank.json.bak`、按 ID 去重、原子写**
（`os.replace`，避免写一半崩溃损坏整个题库）。

### 2. 题型判断优先用 subtype，不要靠 score 推测

`enrich()` 曾靠 `score` 推测题型，实测 **216 题里误判 48 题（22%）**：
带公式的选项提取失败 → 多选题被判成填空（没法作答）；
解答题 score 未提取到（为 0）→ 被判成填空（不给答题空间）。

正确顺序：`subtype`（标注阶段确定的）→ 无则兜底推测。

### 3. 填空判分不能用 includes

曾写 `e.includes(g) || g.includes(e)`，导致
**答案是 12、学生答 1 也判正确**。后果是孩子永远被判对，
错题进不了复习队列，整套间隔复习失效。

现在改为：按空拆分 → 数值比较（`3/4` == `6/8` == `0.75`）→ 字符串精确匹配。

注意 `norm()` 会删掉 `.`（`0.75` → `075`），
所以填空判分必须用专门的 `fillKey()`，保留小数点。

### 4. 年份不能用 0000 兜底

两份无年份的同科目卷会共用 `P-0000-001` 这类 ID，
**后导入的静默覆盖先导入的**。

现在三级回退：文件名 → PDF 正文前 3 页 → **仍失败则报错拒绝**，
提示用户把文件名改成含年份的形式。

### 5. 多空分隔符不能包含 `/`

否则分数 `3/4` 会被拆成 `["3", "4"]`，判分全错。
只用中文分号、逗号、顿号、竖线分隔。

## 七之三、AI 录入流程（标准作业程序）

从教辅 PDF 录题的完整流程。**每一步都有对应工具，跑不过就别往下走。**

流程同时维护在 `skill/references/00-core.md`，
README 这份是给"看项目全貌"的人读的，skill 那份是给执行者读的。

### 总览

```
1. 定位原文    按题型 ID 找到 PDF 页码，读到【答案】【详解】
2. 重建题干    公式还原为规范 LaTeX，丢了的括号补回来
3. 独立验算    不抄原书答案，自己算一遍（数值扫描 / 解析推导）
4. 入库        add_many 整批校验，任一题有问题整批拒绝
5. 导出样卷    HTML + Word
6. 逐题核对    check_render.py，用题干锚点确认两端都存在
7. 跑回归      后端 / 前端 / 文档自检
8. 交付四份文件  HTML、Word 试卷、Word 答案卷、Excel
```

### 1. 定位原文

教辅每题带题型 ID（`M-T-012-V1`= 第 12 题型变式 1），
页码从 `tools/_toc_pages.json` 查：

```python
import json
PAGES = json.load(open('tools/_toc_pages.json', encoding='utf-8'))
print(PAGES['M-T-012'])     # 231
```

必须读到 **【答案】和【详解】两块**。
只读题干等于没审——原书笔误全靠详解反推。

`ref_bank.json` 存着机械提取的原文，可作起点，但它有已知缺陷：

| 缺陷 | 后果 |
|---|---|
| 答案写在详解末尾、无【答案】标记的题被过滤 | **漏题**（已补录 13 道） |
| 详解片段被误判成题目（靠【答案】锚点校验才压住） | 假题 |
| 括号、分数线、向量箭头是矢量绘制 | 提取不出来 |

### 2. 重建题干

PDF 提取不出来的字符（矢量绘制），按原卷视觉重建：

| 原卷 | 提取结果 | 重建为 |
|---|---|---|
| $f(2-x)$ | `f 2 - x` | `$f(2-x)$` |
| $(0,1)$ | `0,1` | `$(0,1)$` |
| $\frac{1}{4}$ | 上下两行 | `$\frac{1}{4}$` |
| $x_1$ | `x1` | `$x_1$` |

**数集写 `\mathbb{R}` 而非 ℝ**——黑板粗体在很多中文字体里缺字形，
打印出来是方块 □。试卷要给孩子做，出方块比不美观严重得多。

拿不准的上下标**保持平文本**。代价不对称：
判成平文本只少一个上下标，上标判成下标会让孩子算错。

### 3. 独立验算（这步不能省）

**不抄原书答案**。每题自己算一遍，三个手段：

```python
# 数值扫描：一维最值
best = min(f(x) for x in frange(lo, hi, 200000))

# 解析降维：固定一个变量，解关于另一个的方程
# （二维网格 20000×20000 会超时，且精度不如解析法）

# 取等条件回代：把求出的参数代回原式，验证等号成立
```

验算抓出过的问题（部分）：

| 题 | 原书 | 实际 | 错因 |
|---|---|---|---|
| T019-V3 | $\frac{5\sqrt5}{2}$ | $\sqrt5+\sqrt{10\sqrt5}$ | 提取 $\sqrt5$ 时漏了分子 |
| T023-E1 | $(0,\frac{\sqrt6}{6}]$ | $(\frac25,\frac{\sqrt6}{6}]$ | 把 $t^2$ 的范围当成 $t$ 的 |
| T098-E1 | 综述"单调递增" | 单调递减 | 前文推导对，末尾写反 |
| T100-E1 | 提示是 $\frac{x+a}{e^x}$ | $x+ae^{-x}$ | 导数与极小值对不上 |

**发现原书错误时按正确值录入，并写进 `review` 字段。**

### 4. 入库

```python
from hand_input import add_many
add_many(items)     # 整批校验，任一题有问题整批拒绝
```

每题必须带：

```python
{
    'type': '选择',                    # 选择 / 填空 / 解答
    'stem_text': '...$f(x)$...',
    'opts': [['A', '...'], ['B', '...']],
    'answer': 'A',
    'src': '2024热点题型归纳 M-T-012-V1',   # 必须写 ref_bank key
    'review': '原书答案缺根号，实为 √2（数值扫描确认）',
}
```

**`src` 必须写完整的 ref_bank key**（`M-T-012-V1`），
不能只写题型（`M-T-012`）。只写题型会被识别为 0 题，
导致清单"待录数"虚高——踩过两次。

### 5~6. 导出与核对

```bash
python3 py/main.py compose-ref --topic M-T-012 --out html/试卷-第3批.html
python3 tools/check_render.py      # 逐题两端核对
```

`check_render.py` 用**题干去公式后的纯中文片段**做锚点，

## 九、打包分发

```bash
npm run tauri build
```

产物在 `src-tauri/target/release/bundle/`：
- Windows：`.msi` / `.exe`
- macOS：`.dmg` / `.app`
- Linux：`.deb` / `.AppImage`

**打包前注意**：`tauri.conf.json` 的 `bundle.resources`
已包含 `py/**/*` 和 `data/**/*`，Python 处理层会随应用分发。
但目标机器仍需 Python 解释器 —— 若要完全免安装，
需用 PyInstaller 打包 Python 并放到 `src-tauri/py/bin/`。

**Python 解释器查找顺序**（`lib.rs` 的 `python_candidates()`）：

| 优先级 | 来源 | 用途 |
|---|---|---|
| 1 | `GAOKAO_PYTHON` 环境变量 | 指定虚拟环境 / 自定义路径，调试时最快 |
| 2 | 打包内置的 `py/bin/python3` | 分发版本应命中这个，不依赖用户环境 |
| 3 | `python3` | 系统默认（macOS / Linux） |
| 4 | `python` | Windows 上通常只有这个名字 |

候选里允许有不存在的路径，会逐个尝试并跳过失败项。
**不要预先做 `exists()` 过滤** —— 打包后资源解压晚于函数调用，
过滤会误判成「没有解释器」。

### 第二轮审核：cases 的两个坑（一个是我自己挖的）

**① 我上一轮的"修正"把公式整段弄丢了。**

怀疑 Word 的 `m:dPr` 不够标准，于是把分隔符改成数字实体 `&#0;`。
结果 **XML 1.0 不允许空字符的字符引用**，
`parse_xml` 抛异常 → `omml_math` 返回 None → `rich()` 跳过 →
**整个分段函数静默消失**，比原来更糟。

同时把 `sepChr` 改成了 `&#124;`（`|`），而这个属性是
**行内列分隔符**，会在「表达式」和「条件」之间插一根竖线。

已撤回：`endChr` 和 `sepChr` 都回到 `m:val=""`，
只保留 `grow="on"` 与 `shp="match"`（这两项是真的缺）。

**② 清洗数据只改了 stem_text，没改 stem 列表。**

`_prep_fields` 是 stem 列表优先，脏的 stem 会把干净的 stem_text 覆盖回去。
`underline` 踩了一次，`\par` 又踩一次 —— 同一个坑两轮。

**新增保险**：`paper_template.CASES_MODE` 可切 `"text"`，
遇到「括号在、内容空白」时改一个字即可降级，不用动逻辑。

**回归用例**：新增 XML 合法性校验 —— 直接断言
`rich()` 之后段落里真的有 `<m:oMath>` 和 `<m:d>`，
而不是检查生成的字符串（字符串看着对，解析可能失败）。

### 第三轮审核：cases 的两个硬错误（前两轮都判断错了）

用户连报两轮「Word 括号在、内容空白」，我前两轮分别猜是
「dPr 不够标准」「XML 非法字符」，**都不对**。第三轮翻 OOXML 规范才找到：

**① `m:e` 里直接放 `m:mr`，缺了 `m:m` 矩阵层。**

**② `m:dPr` 里放了 `m:algn`** —— 而 CT_DPr 的 sequence 只有
begChr / sepChr / endChr / grow / shp / ctrlPr，**没有 algn**。
列对齐要写在 `m:mcPr` 的 `m:mcJc` 里。

教训：**猜不如查规范**。前两轮都在凭印象"修正"，越改越糟；
第三轮直接查 OOXML schema，两个错误一次定位。

### 「f(x) 括号特别大」的真因不是 cases

我一直以为是 cases 的 `{`，于是调 rowspacing / framespacing /
displaystyle=false，收效甚微。

**实际是 `<mo>(</mo>` 默认 `stretchy=true`** —— 它和 cases 在同一个
mrow 里，被 2 行高的 cases 一起拉伸了。

定界符 `()[]|` 改为 `<mo stretchy="false">` 即可，
且 Word 端 OMML 本来就不拉伸，两端反而更一致。

### 答案行用 R() 而非 rich()

`build_answer` 里解析用 `rich()`、答案用 `R()` —— 同一函数两样写法。
结果是答案里的 LaTeX 原样显示（用户看到的 "in" 来自 `
otin`）。

答案、来源、解析、选项，**凡可能含 LaTeX 的字段都必须用 `rich()`**。

### 本轮自己的两个坑

1. **注释里写 `\notin`，Python 解释成换行符** → 文件 SyntaxError。
   LaTeX 相关字符串一律用 raw 前缀。
2. **过时的测试断言要删**：上一轮的 `('shp','algn')` 在移除 algn 后
   永久失败。留着会让人习惯性忽略红色输出。

### 第四轮审核：两个隐蔽的静默失败

**① `∈` 在 Word 里显示成 `in`（只在 Word 端）**

`x\in\mathbb{Z}` 的展开顺序错了：
`\mathbb` 先展开成 `Z`，于是 `\in` 后面变成字母 `Z`，
被负向前瞻 `(?![a-zA-Z])` 挡住 → 不替换 → 落到"未知宏"分支
去掉反斜杠 → 输出 `xinZ`。

**为什么只在 Word 端**：HTML 走 `latex_inline` 递归解析，
不用 `latex_expand`。所以 HTML 正常、Word 异常。
—— 这类差异必须两端同时验证。

修法：把 GREEK + MACRO 移到 `\mathbb` 之前。
试卷 Word 的 ∈ 从 3 个恢复到 10 个，与 HTML 一致。

**② 第6题 A 选项 `A∩B=arnothing`（HTML）/ 空白（Word）**

录入时用了非 raw 字符串，`\varnothing` 的 `\v` 被 Python
解释成垂直制表符 U+000B，库里存的是 `\x0barnothing`：

- HTML：`\x0b` 不可见 → 显示 `arnothing`
- Word：U+000B 是 XML 非法字符 → `parse_xml` 抛异常
  → 公式被整体丢弃 → **空白**

两端都不报错。已加 `repair_ctrl()` 两层防护并清理数据。

**本轮自己的坑**：第一版 `repair_ctrl` 用替换字符串
`'\\' + letter`，被 re 当转义序列吃掉，**修复完全没生效**。
改用 lambda 才对。

### 扫描控制字符必须 load 之后再扫

JSON 文本里控制字符是字面的 `\u000b` 六个字符，
扫原始文本永远扫不到 —— 必须 `json.load()` 之后再扫。

### 第2批录入：`\sqrt6` 在 Word 端不渲染（只影响一端）

第2批基本不等式录入后扫描答案卷，发现 13 处 `sqrt` 源码泄漏。

**根因**：`\sqrt` 后跟单字符（无花括号）时，
`split_rich()` 只认 `\sqrt{..}`，切不出 S 段 → 落到未知宏分支。
上下标早就有补花括号的逻辑（`x_1 → x_{1}`），`\sqrt` 漏了。

**只影响 Word 端** —— HTML 端 `latex_inline` 是递归解析器，
自己能处理单字符参数。又是一例两端路径不同导致的差异。

**修法**：`latex_expand` 末尾补花括号，两个排除条件防止误伤
（已有花括号/可选参数不动；不吃反斜杠，避免 `\sqrt\frac{1}{2}` 被切坏）。

**为什么之前没暴露**：录入时习惯写 `\sqrt{6}`，
这次写了一批 `\sqrt6` 才触发。数据层也一并规范化（28 处）。

### 检测模式写错会造成误报

扫描脚本里用 `>6<` 检测 `\sqrt6` 泄漏，结果匹配到了
`<mn>6</mn>` —— 这是正常的数字标签，不是泄漏。

**检测源码泄漏要用命令名的文本形态**（`>sqrt<`），
不要用内容字符 —— 后者会匹配到正常渲染结果。
